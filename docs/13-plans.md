## Не реализовано

### data.md — §17: Груз контейнера как TMap

**Цель:** заменить массив `cargo: [{ itemId, qty }]` на TMap `cargo[id] = кг`.
Один ресурс — одна запись, независимо от количества килограммов.

**Текущий формат:**
```javascript
{
  itemId: 'container_id',
  qty: '1',
  cargo: [
    { itemId: 'iron_id', qty: '1' },
    { itemId: 'iron_id', qty: '1' },
    // ... 118 строк по 1 кг
  ]
}
```

**Целевой формат:**
```javascript
{
  itemId: 'container_id',
  qty: '1',
  cargo: {
    'iron_id': 120,
    'copper_id': 3
  }
}
```

**Правила:**
- Ключ — **id объекта-ресурса** (stable, не имя).
- Значение — вес в кг, целое число ≥ 0.
- Нулевые ключи не хранятся.
- Пустой груз — `{}`.
- Прямой `holds[].cargo` не вводим: груз только внутри контейнера.

**Совместимость:**
- `makeCargo` и `cleanCargo` принимают оба формата.
- Старый массив схлопывается по `itemId`.
- После первой загрузки данные сохраняются в формате карты.
- Невалидные ключи отбрасываются.

**Что меняется в коде:**

| Файл | Изменения |
|------|-----------|
| `store.js` | `makeCargoMap`, `cargoMass`, `addCargo`, `sellCargo`, `sellEntry` |
| `hangar/js/ship.js` | `shipCargoRows`, `cargoChipsHTML`, `showCargoTip` |
| `hangar/js/app.js` | продажа по `resourceId` вместо `cargoIndex` |
| `hangar/js/shop.js` | карточка контейнера, продажа вместе с грузом |

**Критерии готовности:**
- [ ] Покупка 120 кг железа → одна запись `cargo['iron_id'] = 120`
- [ ] Повторная покупка увеличивает значение
- [ ] Продажа 1 кг уменьшает, при нуле ключ исчезает
- [ ] Два контейнера — независимые карты
- [ ] Старый массив загружается без потерь

### data.md — §18: Обязательная масса у кораблей и оборудования

**Цель:** масса становится **обязательным свойством** любого корабля и оборудования.
Ресурсы по-прежнему безмассовые.

**Правила:**
- У корабля и оборудования масса задана явно и > 0.
- У ресурса свойства «Масса» нет.
- Контейнер и бак — оборудование: масса обязательна.
- Отсутствие массы — **ошибка данных**, не «1 кг по умолчанию».
- Старые объекты без массы → список проблем в админке.

**Изменения:**
- Каноническое свойство: **«Масса»**. Слияние «Вес» → «Масса».
- Свойство «Масса» добавляется в `propIds` корней «Оборудование» и «Корабли».
- У корня «Ресурсы» массы нет.
- Старое поле `object.mass` → `values[massPropId]`.
- Пустое, ноль, NaN, отрицательное — ошибка.

**Что меняется:**
- `hasMass`, `massIssue`, строгий `cargoUnitsOf`.
- Проверки массы в `buyForShip`, `buyShip`, `holdFor`.
- Обязательное поле массы в админке, блокировка сохранения без массы.
- Предупреждения в таблицах, счётчик «Без массы» на главной.
- Запрет удалять «Массу» у корней групп.

## Реализованные планы

### sky-parallax.md — Параллакс неба

**Что сделано:**
- Небо реагирует на панорамирование: параллакс ~4% с насыщением (tanh).
- Небо реагирует на зум: мягкий рост масштаба (2^(ZK * log2(zoom))).
- Оверскан-кэш: канвас W×1.2, H×1.2, 10% запаса.
- Три слоя звёзд: дальний (k=0.10, ~700), средний (k=0.35, ~450), ближний (k=1.0, 400).
- Бесконечные тайлы для слоёв Б/В.

### small-bodies.md — Малые тела

**Что сделано:**
- Главный пояс: 400 частиц, щели Кирквуда, 4 крупнейших тела.
- ОЗА: 14 именованных + 6 сгенерированных (Amor/Apollo/Aten).
- Троянцы Юпитера: L4/L5 облака с либрацией.
- Кометы: 4 штуки с ядром, комой, хвостом от Солнца.
- Пояс Койпера: 600 частиц.
- Облако Оорта: 350 частиц.
- Блок «03 Малые тела» в боковой панели.
- Метеоритные строки (марсианские ≈300, лунные ≈500).

### isometric.md — Проекция 2:1

**Что сделано:**
- Диметрия 2:1: `y *= 0.5`, `z` проецируется как `y -= z * 0.866`.
- Raw-эклиптика для физики, view для отрисовки.
- 3D-орбиты с реальными inc/node (`keplerPos3`, `orbitPoint3`).
- Сферы с бликом и тенями на полу.

### admin-categories-width.md — Таблицы категорий

**Что сделано:**
- Таблицы категорий на всю ширину, как в оборудовании.
- Единый стиль таблиц в админке.

### plan-workflow.md — План работ

**Что сделано:**
- Порядок: план → одобрение → ветка → изменения → подтверждение → коммит.

## demo-server.md — Мультиплеерный сервер

**Статус:** не реализовано, есть только план.

**Цель:** аналог Firebase для проекта.

**Стек:** Python (websockets, bcrypt), SQLite, JWT.

**Требования:**
- 200+ одновременных WebSocket подключений.
- Время отклика < 50 мс.
- База до 1 ГБ.

**Модель данных:**
- `users` — регистрация, bcrypt.
- `sessions` — онлайн-сессии, позиции.
- `world_changes` — история действий в мире.

**API:**
- HTTP: `/api/auth/register`, `/api/auth/login`, `/api/health`
- WebSocket: `join`, `position`, `action`, `leave`

**Клиентская библиотека:** MiniFirebase (JS).

## Нефункциональные требования

- Время отклика сервера: < 50 мс.
- Поддержка: до 200+ одновременных подключений.
- Размер базы: до 1 ГБ.
- Код: только Python и JavaScript, без сборщиков.

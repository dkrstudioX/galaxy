## Звёздные базы игрока (bases.js)

### Хранение

Три ключа localStorage, обособленных от данных админки/ангара:

| Ключ | Назначение |
|------|-----------|
| `galaxy_space_bases_v1` | Активные базы |
| `galaxy_space_base_names_v1` | Реестр имён баз |
| `galaxy_space_bases_removed_v1` | Архив удалённых баз |

### Схема записи базы

```javascript
{
  id: 'base-luna-orbit',
  name: 'HELIOS OUTPOST',
  nameId: 12,           // индекс в BASE_NAMES
  nameCount: 3,         // номер использования имени
  status: 'active',     // 'active' | 'removing' | 'removed'
  hostKind: 'moon',     // 'planet' | 'moon'
  planet: 'Earth',
  moon: 'Moon',
  orbitRadius: 250,     // радиус орбиты (единицы мира)
  period: 1.0,          // период обращения, суток
  phase0: 0.5,          // фаза орбиты, радианы
  created: '2026-10-22T...',
  fleet: true,          // стартовая база игрока
  removeEndsAt: 0,      // только 'removing': конец разбора, ms Date.now()
  removedAt: null,      // только 'removed': когда разбор закончился
  x: 0, y: 0            // только в памяти: позиция на карте (каждый кадр)
}
```

### Статусы базы

| Статус | Описание |
|--------|----------|
| `active` | Работает, видна на карте |
| `removing` | Удаляется, идёт таймер 4 секунды |
| `removed` | Удалена, запись в архиве |

### Коридор орбиты

Радиус орбиты базы ограничен коридором `baseRadiusRange`:

1. **Не ниже поверхности хозяина** (запас `BASE_CLEAR`).
2. **Не выше ближайшей полосы:**
   - Диск Солнца
   - Полосы соседних планет (база у Меркурия не дотягивается до Венеры)
   - У базы на планете — луны планеты (включая невидимые при зуме)
   - У базы на луне — планета под ней и луны-соседи
3. **`BASE_MAX_R`** — абсолютный потолок.
4. **Разведение с другими базами** того же хозяина (`fitBaseRadius`, зазор
   `BASE_SAME_GAP`).

Если свободного места нет — база прижимается к поверхности хозяина.

### Правило ближайшего тела

При создании/перемещении базы:
- Соседи (планеты и видимые луны) снимаются **один раз** при старте режима
  (snapshot в `baseMode.snap`).
- Как только орбита дальше половины пути до другого тела — база переезжает
  к ближайшему телу.
- База у Венеры, уведённая к Земле, станет базой Земли.

### Создание базы

```
1. Клик «Создать базу» в карточке планеты/луны
2. Включается режим `state.baseMode`
3. Радиус орбиты следует за курсором
4. Курсор определяет сторону орбиты (`mode.ang`)
5. Клик — создать базу
6. Esc / правая кнопка — отмена
```

### Удаление базы

```
1. Клик «Удалить базу» → confirmDialog (стиль ангара)
2. После согласия: статус 'removing', таймер BASE_REMOVAL_MS (4 с)
3. Имя на карте краснеет, под ним полоска прогресса `.rm-bar`
4. По истечении: запись → статус 'removed', запись в архив
5. Место в реестре имён помечается `removed`
```

### Подпись базы на карте

- Невидимая панель фиксированной ширины `BASE_LABEL_W` (96 px).
- Длинное имя режется с «…».
- При наведении — бегущая строка влево (имя уезжает, читается целиком).
- Полоска разбора — во всю панель, справа налево.
- Кегль постоянный: Manrope 600, 10 px.

### Реестр имён

```javascript
// galaxy_space_base_names_v1
{
  v: 1,
  names: {
    '0': { id: 0, name: 'HELIOS OUTPOST', count: 3, bases: [...] },
    '1': { id: 1, name: 'FRONTIER STATION', count: 1, bases: [...] }
  }
}
```

- `count` — сколько раз имя выпадало (не сбрасывается).
- `bases[]` — где стоят базы с этим именем.
- Повтор получает суффикс « - 2», « - 3».

### Стартовая база LUNA-ORBIT

- `id: 'base-luna-orbit'`, флаг `fleet: true`.
- Не участвует в реестре имён.
- Мигрируется при загрузке, если записи нет.
- В карточке показывает список купленных кораблей из `Store.userShips()`.

## Кластеризация тел (scene.js)

### clusterBodies

```javascript
scene.clusterBodies(bodies, zoom)
// bodies: массив тел кадра
// zoom: текущий зум
// возвращает: массив групп, каждая — { anchor, items[], baseIds[] }
```

**Правила:**
- Тело встаёт в группу ближайшего представителя **той же системы** (`system`).
- `system` = имя планеты у планеты и лун, `null` у малых тел.
- Порог: `MERGE_PX = 50` экранных пикселей.
- Планеты, луны, солнце и кометы — **якоря** (`anchor`): видны всегда, в чужую
  группу не входят.
- Луна не «прилипает» к пролетавшему астероиду.
- Кометы не пропадают.

### Подпись группы

У представителя группы подпись в две строки:
1. Имена всех тел группы через запятую (планеты — русским именем, малые — `ru`)
2. Базы игрока на телах группы (цианом, цветом баз)

### placeLabel

```javascript
scene.placeLabel(x, yTop, w, h)
// Возвращает сдвиг по вертикали, чтобы подпись не перекрывалась
// Если места нет (16 шагов) — подпись остаётся на месте
```

- Начинается заново каждый кадр (`resetLabels()`).
- Порядок: сначала подписи групп, затем имена баз.

## Система неба (sky.js)

### Два слоя

**1. Глубокое небо (offscreen-canvas кэш):**
- Полоса Млечного Пути под ~60° к эклиптике
- Тёмная пылевая полоса
- Цветные туманности
- Галактика Андромеды
- Магеллановы облака
- Звёздная пыль полосы (~900 точек, 10–15 ярких звёзд с ореолом)

**Параллакс:**
- Смещение: `shift = MAX * tanh(K * cam / MAX)`
- `MAX = 5%` размера экрана, `K ≈ 0.04`
- Малая панорама — небо отстаёт на ~4% (классический параллакс)
- Большая панорама — насыщается (небо «бесконечно далеко»)

**Зум неба:**
- `scale = 2^(ZK * log2(zoom))`
- `ZK ≈ 0.03`, ограничение `[0.94, 1.15]`
- Каждое удвоение зума — лёгкое «наезжание» на небо

**Оверскан-кэш:**
- Канвас `W×1.2, H×1.2` (10% запаса на сторону)
- Блит: `drawImage(skyCanvas, dx, dy, bw*scale, bh*scale)`
- Максимальное смещение (5%) + разница масштаба (≤6%) < запаса (10%)
- Пересборка кэша — только при resize окна

**2. Звёзды галактики (два тайлящихся слоя):**

| Слой | k | Кол-во | Описание |
|------|---|--------|----------|
| Дальний | 0.10 | ~700 | Мелкие, слабое мерцание |
| Средний | 0.35 | ~450 | Крупнее, мерцание заметнее |

- `k` — доля экранного пути мира, которую проходит слой (мир = 1.0).
- Тайл размером с экран + копии со сдвигом ±T.
- Зум: `zoom^k` — дальние почти не разлетаются.
- Мерцание — от `state.time` (синус).

### Звёзды мира (scene.js)

- 400 точек в мировой системе (k = 1.0).
- Ближний слой: двигаются и масштабируются как мир.
- Мерцают синусом от `state.time`.

### Вызов из render.js

```javascript
// render.js — до мировых координат
drawSky(ctx)
// 1. Блит offscreen-кэша неба
// 2. Звёздные слои Б/В
// 3. Мировые звёзды (scene.js)
```

## Группировка тел (groupPlan)

Универсальный механизм группировки:

```javascript
scene.groupPlan(items, fit, { nameOf, baseOf })
// items: массив тел
// fit: функция фильтрации (например, moonGroupPlan)
// nameOf: функция получения имени
// baseOf: функция получения баз
// возвращает: { items[], anchor, baseIds[] }
```

Применяется к:
- Лунам (moonGroupPlan)
- Крупнейшим телам пояса
- ОЗА по классам (amor/apollo/aten)
- Троянцам L4/L5
- Кометам

## Порядок отрисовки мира (render.js)

```
1. drawSky(ctx)                          — глубокое небо
2. drawStars(ctx)                        — мировые звёзды
3. drawSun(ctx)                          — солнце (glow + sphere)
4. drawOrbits(ctx)                       — орбиты планет (постоянные)
5. drawShadows(ctx)                      — тени под телами
6. drawSpheres(ctx)                      — сферы планет и лун
7. drawSmallBodies(ctx)                  — астероиды, кометы
8. drawBases(ctx)                        — звёздные базы
9. drawLabels(ctx)                       — подписи (placeLabel)
```

## 0. Контекст проекта

Galaxy Admin — статическая SPA на чистом JavaScript (без сборки и зависимостей).
Вход — `index.html` (портал), панель — `admin.html`. Проверка: поднять
`python -m http.server 8642` в корне и открыть `http://127.0.0.1:8642/admin.html`.

Файлы:
- `js/store.js` — данные в localStorage (ключ `galaxy_admin_db_v1`), миграция и
  санитизация в `sanitize()`/`pruneRefs()`, демо-данные в `demoData()`,
  публичный `Store`.
- `js/app.js` — hash-роутер (`ROUTES`) и боковая навигация.
- `js/ui.js` — DOM-хелперы: `UI.h/modal/input/select/table/...`.
- `js/pages/catalogs.js` — «Свойства», «Слоты», «Категории кораблей/товаров».
- `js/pages/objects.js` — «Корабли», «Товары», редактор слотов `buildSlotsSection`.
- `js/pages/home.js` — сводка, экспорт/импорт, демо-данные.
- `css/styles.css` — тёмная тема, стили дерева категорий (`.tree-cell` и др.).

Текущая модель (после коммита `997ff70`):
- `props: [{id, name, value}]` — свойства.
- `slots: [{id, name, capacity}]` — слоты; `capacity` пусто = ∞.
- `categories: [{id, type: 'ship'|'goods', name, propIds, parentId}]` — два дерева,
  подкатегория наследует свойства родительской.
- `ships: [{id, name, categoryId, values, slots: [{slotId, contents: [{itemId, qty}]}]}]`
  — у корабля свои слоты с содержимым.
- `goods: [{id, name, categoryId, values, mass, slotId}]` — `slotId` = «в какой слот
  вставляется», `mass` = масса единицы.

## 1. Цель (что хочет пользователь)

1. Убрать «Категории кораблей» и «Корабли» — и страницы, и сущности.
2. Оставить одну сущность вместо двух: «Объекты» (бывшие товары + корабли).
3. Категории — «просто категории»: одна страница, одно дерево без деления на типы
   (деревья кораблей и товаров сливаются в одно).
4. У объекта есть флажок «это корабль»: у корабля — собственные слоты с содержимым,
   у остальных — «в какой слот вставляется» либо отметка «в любой слот».
5. Свойства — у категорий (категория задаёт набор), значения — у объекта;
   наследование по дереву сохраняется.

Уточнение от 17.10.2026 (принято в работу): флажок «корабль» — поле объекта, а не
общая пара полей у каждого подряд; это уточняет пункты 2 и 4 в §7.

## 2. Целевая модель данных

```
{
  props: [{ id, name, value }],
  slots: [{ id, name, capacity }],
  categories: [{ id, name, propIds: [propId], parentId }],      // без type
  objects: [{
    id, name, categoryId,
    values: { propId: value },
    mass,                                   // масса единицы, '' = 0
    isShip,                                 // true — корабль
    slots: [{ slotId, contents: [{ itemId, qty }] }],  // только у корабля
    slotId                                  // только у не-корабля, null = любой слот
  }]
}
```

Пояснения:
- `isShip: true` — у объекта свои слоты (`slots`), сам он никуда не вставляется
  (`slotId = null`).
- `isShip: false` — `slotId` задаёт конкретный слот, `null` — в любой; `slots` пуст.
- `contents.itemId` ссылается на `objects`, `qty` — количество; масса содержимого
  слота считается как `qty × mass`.
- Инварианты (поддерживаются `sanitize()`/`pruneRefs()`): все ссылки существуют;
  родитель категории существует и цепочка не зацикливается; объект не лежит в своём
  же слоте; у корабля `slotId` сброшен, у не-корабля `slots` пуст; имя категории
  уникально среди соседей (проверяется в UI).

## 3. Миграция старых данных

- Ключ localStorage не меняем — данные пользователя мигрируют на месте.
- Категории: поле `type` отбрасывается, обе ветки становятся одним деревом;
  `parentId` сохраняется, невалидный родитель → корневая (уже делает `fixParents`).
- Объекты собираются из `objects` + `goods` + `resources` + `equipments` + `ships`:
  - из кораблей: `isShip: true`, `slotId: null`, `slots` переносятся как есть;
  - из товаров: `isShip: false`, `slots: []`, `slotId` как был;
  - из `objects` нового формата: `isShip` из поля, иначе `false`.
- Старые JSON-выгрузки продолжают импортироваться: санитизация читает все
  перечисленные коллекции и отбрасывает лишние поля.

## 4. Изменения по файлам

- `blank()` → `{ props, slots, categories, objects }` (убрать `ships`, `goods`).

## 6. Как проверять

- Node-стенд (временный файл, в репозиторий не коммитить): импорт старого формата
  с `ships` + `goods` + `resources`/`equipments` → одна коллекция `objects`,
  категории без типа, дерево и пути, наследование свойств, `slotUsage`,
  `objectUsage`, round-trip export → import.
- Headless Chrome (временная страница-стенд, как при проверке дерева категорий):
  в навигации нет «Кораблей» и «Категорий кораблей»; `#/ships` и `#/goods`
  уводят на `#/objects`; `#/categories` показывает одно дерево; модалка объекта
  содержит и «Вставляется в слот», и собственные слоты; перегрузка слота по массе
  даёт ошибку; удаление объекта, лежащего в чужом слоте, запрещено; счётчики
  главной совпадают с данными.
- Ручной прогон: «Загрузить демо-данные» → просмотреть категории и объекты;
  «Очистить всё» → создать категорию, свойство, слот и объект с нуля.

## 7. Открытые вопросы (принятые по умолчанию решения)

1. Имя сущности: «Объекты» (hash `#/objects`, коллекция `objects`), слово «Товары»
   уходит. Если нужно оставить «Товары» — меняется только `label` и hash.
2. «Слоты для всех объектов» — решено флажком «это корабль» (уточнение 17.10.2026):
   корабль получает список слотов, не-корабль — «в какой слот вставляется» или
   «в любой слот»; общей пары полей у каждого объекта нет.
3. «Свойства для категорий» — как сейчас: категория задаёт набор свойств, значения
   живут у объекта. Если нужны ещё и значения свойств у самой категории (значения
   по умолчанию для всей ветки) — это отдельный шаг: `categories[].values` и
   подстановка в форму объекта.
4. В списки слотов корабля попадают только объекты с `isShip: false` (уточнение
   17.10.2026): сами корабли в чужие слоты не вставляются.
5. Дубли имён категорий после объединения типов не переименовываются: при импорте
   остаются как есть, новые дубли в одной ветке блокирует UI.

## 8. Риски

- Миграция необратима: перед первым запуском новой версии сделать «Экспорт JSON».
- Тихая потеря: если объект удалить, пока он лежит в чужом слоте, `pruneRefs()`
  вычистит его при следующей загрузке. Поэтому запрет удаления через `objectUsage`
  обязателен, а не «желателен».
- Ссылка объекта на самого себя запрещается; вложенность слотов рендерится на один
  уровень (содержимое слота показывает имя объекта, а не его собственные слоты) —
  это осознанное ограничение.
- Объёмы данных небольшие (сотни записей), оптимизации не требуются.

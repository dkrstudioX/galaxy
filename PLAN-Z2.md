# План Z2: объединение ресурсов и оборудования в «Товары»

Статус: выполнен (14.10.2026, ветка `Z2`). Ветка: `Z2` (создана от `Z`). План написан так, чтобы его мог
выполнить другой человек или AI-модель без дополнительного контекста беседы.

## 0. Контекст проекта

Galaxy Admin — статическая SPA-панель на чистом JavaScript (без сборки и
зависимостей). Открывается как `index.html`; для проверки удобно поднять
`py -m http.server 8642` в корне и открыть `http://127.0.0.1:8642/index.html`.

Файлы:
- `js/store.js` — слой данных, localStorage (ключ `galaxy_admin_db_v1`),
  миграция/санитизация в `sanitize()`, демо-данные в `demoData()`.
- `js/app.js` — hash-роутер (`ROUTES`), боковая навигация.
- `js/ui.js` — DOM-хелперы: `UI.h/modal/input/select/table/...`.
- `js/pages/catalogs.js` — страницы «Свойства», «Слоты», «Категории».
- `js/pages/objects.js` — страницы «Корабли», «Ресурсы», «Оборудование»;
  редактор слотов корабля `buildSlotsSection` с содержимым и вместимостью.
- `js/pages/home.js` — экспорт/импорт JSON, демо-данные, очистка.
- `css/styles.css` — оформление (тёмная тема).

Текущая модель данных (после ветки Z, коммит `b2dc6df`):
- `props: [{id, name, value}]` — свойства.
- `slots: [{id, name, capacity}]` — слоты; `capacity` пусто/не число = ∞.
- `categories: [{id, type: 'ship'|'resource'|'equipment', name, propIds}]`.
- `ships: [{id, name, categoryId, values, slots}]`, где
  `slots: [{slotId, contents: [{kind: 'equipment'|'resource', itemId, qty}]}]`.
- `resources` и `equipments` (отдельные коллекции):
  `[{id, name, categoryId, values, mass, slotId}]` — `slotId` = «в какой слот
  встанет», `null` = в любой; `mass` — масса единицы, учитывается вместимостью.

## 1. Цель (что хочет пользователь)

1. Ресурсы и оборудование — **одна сущность «Товар»** и **одна таблица**
   «Товары» вместо двух страниц.
2. Категории ресурсов и категории оборудования — **одна страница
   «Категории товаров»** (`type: 'goods'`).
3. При наполнении слота корабля **не нужно выбирать тип** (оборудование или
   ресурс) — просто выбираешь товар. Селектор «тип содержимого» исчезает.
4. Всё существующее должно мигрировать без потерь: старые localStorage-данные
   и старые JSON-выгрузки (в репозитории лежат примеры
   `galaxy-admin-data.json` и `galaxy-admin-data (1).json` — старого формата).

## 2. Целевая модель данных

- `goods: [{id, name, categoryId, values, mass, slotId}]` — бывшие
  `resources` + `equipments`, формат записи не меняется.
- `categories`: вместо `type: 'resource'|'equipment'` — единый
  `type: 'goods'`; `type: 'ship'` остаётся.
- `ships[].slots[].contents`: `[{itemId, qty}]` — **без поля `kind`**,
  `itemId` теперь указывает на `goods`.
- `slots`, `props` — без изменений.

## 3. Изменения по файлам

### 3.1. `js/store.js`
- `blank()`: `{props, slots, categories, ships, goods}` (вместо
  `resources`/`equipments`).
- `sanitize()`:
  - категории: `type === 'ship'` остаётся; `'resource'` и `'equipment'`
    мигрируют в `'goods'`; прочее — `'goods'`.
  - товары: новые `data.goods`; для совместимости со старыми выгрузками
    склеить `data.resources` и `data.equipments` (старые поля читаются).
  - содержимое слотов: убрать `kind`; `itemId` ищется в `goods`. При миграции
    старых данных `kind` просто отбрасывается (id уникальны).
- `pruneRefs()`: ссылки `categoryId` по категориям `'goods'`; содержимое
  слотов чистится по `goods`; `slotId` у товаров как раньше.
- `TYPE_LABEL`: `{ship: 'корабли', goods: 'товары'}`.
- `slotUsage`, `categoryUsage` (коллекция `goods`), `counts`
  (поле `goods` вместо двух), `massOf`/`usedMass`/`slotCapacity` — на `goods`.
- `createObject('goods', ...)` — единый путь; хелпер
  `Store.goods()`.
- `demoData()`: те же предметы одной коллекцией; категории `resource`/
  `equipment` заменить на две категории `goods` («Металлы», «Кристаллы»,
  «Оружие», «Двигатели», «Защита», «Прочее» — можно объединить по вкусу);
  содержимое слотов без `kind`.
- Экспорт/импорт: формат меняется автоматически (санитизация при импорте
  ест и старые, и новые файлы).

### 3.2. `js/app.js`
- `ROUTES`: убрать `#/resources` и `#/equipment` → один `#/goods`
  «Товары» (раздел «Объекты»); `#/categories/resource` и
  `#/categories/equipment` → `#/categories/goods` «Категории товаров».
  Старые хэши можно оставить редиректом на новые (по желанию).

### 3.3. `js/pages/objects.js`
- Удалить `RES_META`/`EQ_META` и `renderItems`; одна страница
  `renderGoods` + `openGoodsModal` (бывший `openItemModal` без типа).
- Таблица «Товары»: Название / Категория / Масса / Слот.
- В `buildSlotsSection` и `addContentRow`: убрать селектор типа; списки
  предметов — из `Store.goods()` (совместимость по `slotId` прежняя:
  совпадает или «без слота»); `collect()` возвращает `contents` без `kind`.
- В таблице кораблей сводка содержимого — без различения типов.

### 3.4. `js/pages/catalogs.js`
- `CATEGORY_META`: `ship` + `goods` («Категории товаров», подсказки
  в духе «Например: Металлы, Оружие»).
- `openCategoryModal` — без изменений по сути (type передаётся).

### 3.5. `js/pages/home.js`
- Проверить тексты «что создать» (если перечислены ресурсы/оборудование —
  заменить на товары). Экспорт/импорт не трогать.

### 3.6. `css/styles.css`
- Возможно, ничего. Стили `content-kind` (селектор типа) станут не нужны —
  можно убрать заодно.

## 4. План выполнения (порядок)

1. `store.js` — модель + миграция (шаг 3.1). Проверка в консоли:
   импорт старого `galaxy-admin-data.json` → коллекция `goods` содержит и
   бывшие ресурсы, и оборудование; содержимое слотов без `kind`.
2. `app.js` — маршруты (3.2).
3. `catalogs.js` — категории товаров (3.4).
4. `objects.js` — страница «Товары» и упрощённый редактор слотов (3.3).
5. `home.js` — тексты (3.5); `styles.css` — чистка (3.6).
6. Проверка в браузере (см. §5).
7. Коммит в `Z2`: `feat: merge resources and equipment into goods`.

## 5. Как проверять

- Открыть приложение, «Загрузить демо-данные»: одна страница «Товары»,
  одна «Категории товаров», в навигации нет «Ресурсов»/«Оборудования».
- Редактор корабля: у содержимого слота НЕТ выбора типа — только товар и
  количество; бейдж `занято / вместимость` работает, кламп по массе работает.
- Миграция: до обновления кода открыть приложение со старыми данными
  (или импортировать `galaxy-admin-data.json`) → после обновления данные
  на месте, объединены.
- Round-trip: экспорт → импорт → структура не меняется.
- Удаление товара/категории: проверки использования (`slotUsage`,
  `categoryUsage`) показывают корабли и слоты корректно.

## 6. Открытые вопросы (принятые по умолчанию решения)

- Навигация «Объекты»: Корабли, Товары. Разделы категорий: Категории
  кораблей, Категории товаров.
- Поле `kind` из старых данных отбрасывается при миграции (источник
  коллекции неважен — id уникальны).
- Демо-категории после объединения: 6 штук с типом `goods` (перечислены
  в 3.1); при желании можно сократить.
- Старые маршруты `#/resources`, `#/equipment` просто перестают
  существовать (fallback на `#/home` уже есть в `currentRoute`).

# space/ — Солнечная система (интерактивная карта)

Карта солнечной системы на чистом canvas 2D. Без сборщиков и зависимостей:
ES-модули, раздаются любым статическим сервером. Тест локально:

```
cd C:\work\GalaxyAdminPanel
py -m http.server 8642
# http://127.0.0.1:8642/space/index.html
```

## Структура модулей

```
space/
├── index.html          — разметка + CSS (HUD, кнопки, боковая панель 01–03);
│                         подключает общие ../data/store.js и ../data/icons.js
├── ARCHITECTURE.md     — этот файл
└── js/
    ├── main.js         — точка входа: канвас, init, главный цикл rAF;
    │                     каждый кадр продвигает время и полёт камеры
    ├── config.js       — все константы (время, зум, скорости, цвета, обводки)
    ├── state.js        — единственный мутируемый объект `state` + resize()
    ├── data.js         — данные: planets, moonsByPlanet, Луна/база, moonTree,
    │                     beltNotables/neas/trojanNames/comets (малые тела)
    ├── math.js         — чистые функции: orbitAngle, keplerPos, auToDist,
    │                     makeRng, formatSimDate, clamp, screenToWorld
    ├── scene.js        — генерация фона (stars, asteroids) + visibleMoons(zoom).
    │                     У астероидов — параметры орбиты (d, l0, period); пояс
    │                     движется в render.js от общего simDays
    ├── smallbodies.js  — малые тела: пояс (частицы + щели Кирквуда + крупнейшие
    │                     тела), ОЗА, троянцы L4/L5, кометы (ядро/кома/хвост),
    │                     пыль Койпера и Оорта. Каждое тело — сущность с kind/id;
    │                     именованные отдаются как hover-цели (поле small)
    ├── bases_name.js   — BASE_NAMES: 100 имён новых баз (случайный выбор,
    │                     реестр повторов живёт в bases.js)
    ├── bases.js        — звёздные базы игрока: отдельный ключ localStorage,
    │                     создание/перенос/список, отрисовка маркеров и превью
    │                     выбора орбиты
    ├── input.js        — ввод: тач/pinch, колесо, панорамирование правой
    │                     кнопкой, выбор кликом, режим выбора орбиты базы
    │                     (снимок соседей, правило ближайшего тела)
    ├── render.js       — отрисовка мира: фон, солнце, планеты, луны, базы,
    │                     малые тела. Возвращает hoverTargets для hover.js
    ├── sky.js          — дальний фон (отдельный слой): Млечный Путь под ~60°,
    │                     Андромеда, туманности, Магеллановы облака. Экранные
    │                     координаты, кэш в offscreen-canvas, не связан с игрой
    ├── hover.js        — hit-тест курсора, орбита наведённого тела (у малых
    │                     тел — сэмплированная полилиния), подсказка без рамки
    └── ui.js           — DOM: HUD, боковая панель «01 Карта системы»,
                          «02 Объект», «03 Малые тела»; карточки тел и баз;
                          твин полёта камеры (flyToCamera/updateFlyTo)
```

## Зависимости между модулями (кто кого импортирует)

```
main ────► state, config, input, render, hover, ui
render ──► state, math, config, data, scene, sky, smallbodies, bases
hover ───► state, math, config
input ───► state, math, config, data, hover, ui, bases
ui ──────► state, math, data, config, bases (+ window.Store / window.Icons из data/)
smallbodies ─► state, math, data, config
bases ───► state, math, config, data
scene ───► state, data
sky ─────► state
math ────► config
data, config — ни от кого (чистые данные/константы)
```

Правило: config и data не импортируют ничего кроме друг друга (листья графа);
state знают все, но меняют его только input (камера/зум, режим базы),
ui (режим базы, полёт камеры) и main (время). Циклов нет: input зависит от ui
(выбор и карточка), ui от input — нет; полёт камеры поэтому живёт в ui.js.

## Ключевые концепции

### Время и орбиты — один таймер
`state.simDays` — сутки (дробные) от эпохи J2000. Углы всех тел считаются
из него формулой средней долготы: `угол = L0 + 360° * simDays / период`
(`math.js orbitAngle`). Поэтому счётчик дней, дата и взаимные положения
планет всегда согласованы. Симуляция стартует с реальной текущей даты.
`timeScale` (кнопки внизу) умножает скорость: x2/деление, пределы из config.
Пояс астероидов живёт по тому же таймеру: параметры орбит задаёт `scene.js`
(радиус 270–350, период по закону Кеплера от якорей Марс → Юпитер), позиции
каждый кадр считает `render.js` — пояс вращается и ускоряется вместе со всей
системой.

### Система координат
Мир: солнце в (0,0), орбиты — окружности радиуса `planet.dist`. Камера:
`state.camX/camY` — мировая точка в центре экрана, `zoom` — масштаб.
Перевод экран→мир: `math.js screenToWorld` (обратно — transform в render.js:
translate(W/2,H/2) → scale(zoom) → translate(-camX,-camY)).

### Зум и раскрытие лун (логарифмика)
Зум 0.3x–20x (`config.js`). Число видимых лун у планеты растёт по
логарифмической шкале (`scene.js visibleMoons`): 1 луна при zoom=1, +1 за
каждое умножение зума на ~1.4. Порядок лун в `data.js moonsByPlanet` = порядок
раскрытия (первые — главные луны). Каждая следующая луна рисуется на орбите
дальше от планеты (`p.r + 12 + i*7`).

### Стиль карты — монохром
Все тела: плоские круги без градиентов/спрайтов. Различаются заливкой
и толщиной обводки (значения в `config.js COLORS/STROKE`):
солнце (самая толстая) > планеты > луны (самая тонкая). Цвета планет в
`data.js` используются только точками в боковой панели.

### Орбиты и названия — только при наведении
Постоянных орбит и подписей на карте нет. Каждый кадр render.js возвращает
`hoverTargets` (солнце, планеты и их видимые луны, звёздные базы, именованные
малые тела с позициями); hover.js проверяет попадание курсора (луны и малые
тела приоритетнее — они поверх) и рисует: пунктирную орбиту тела (планета —
вокруг солнца, луна — вокруг планеты, база — вокруг её хоста, у солнца орбиты
нет, у малых тел — сэмплированная полилиния `poly`: эллипс-дескриптор врёт
вне линейных зон `auToDist`) и текстовую подсказку у курсора — просто белый
текст с тенью, без рамки.

### Особый случай: Земля (`hasBase`)
Луна Земли и орбитальная база рисуются отдельным блоком (`render.js
drawEarthMoonAndBase`), не через moonsByPlanet. База — циановый маркер
«BASE» с пульсом; её орбита вокруг Луны показывается всегда.

### База: выбор и купленные корабли
База — полноценная цель выбора (`kind: 'base'` в hoverTargets): hover и клик
работают как у луны, пунктирная орбита — вокруг Луны (`baseOrbitRadius`),
подпись «База LUNA-ORBIT». В блоке «Объект» (`ui.js`) база показывает свои
параметры и список купленных кораблей из общего хранилища проекта:
`window.Store` (`data/store.js`, ключ `galaxy_admin_db_v1`) и иконки
`data/icons.js`. Строки — в формате списка «В продаже» из ангара: иконка,
имя, «Масса N кг», категория и цена покупки. Если Store не подключён или
список пуст — заметка вместо строк; без Store страница работает как раньше
(данные — необязательная зависимость, всё в try/catch).

### Звёздные базы игрока (bases.js)
Созданные игроком базы живут в отдельном ключе localStorage
(`galaxy_space_bases_v1`; данные админки/ангара не задействованы), прикреплены
к планете или луне и летают по круговой орбите радиуса `orbitRadius`. Период —
как у Луны: сутки на радиусе `baseOrbitRadius`, дальше по закону Кеплера;
радиус зажат в коридор `baseRadiusRange`: от поверхности хозяина до
поверхности ближайшего соседа — лун у планеты или планеты у луны —
(`BASE_MAX_R` — абсолютный потолок), так орбита базы не пересекает тела.
Создание: кнопка «Создать базу» в
карточке планеты/луны включает режим выбора орбиты (`state.baseMode`), радиус
следует за курсором, клик создаёт (Esc и правая кнопка отменяют). Сторона
орбиты — направление от центра хозяина к курсору (`mode.ang`): база и в
превью, и в записи встаёт с той стороны, куда указывает курсор (`phase0`
пересчитывается под этот угол, `phaseFor`). Правило
ближайшего тела: соседи (планеты и видимые луны) снимаются один раз при старте
режима (snapshot в `baseMode.snap`) — на движениях мыши позиции не
пересчитываются; как только точка орбиты оказывается дальше половины пути до
другого тела (курсор ближе к нему), орбита переезжает к нему: база у Венеры,
уведённая к Земле, станет базой Земли. У созданной базы в карточке есть
«Переместить базу» — тот же режим, но клик обновляет хост, радиус, период и
сторону (фазу) существующей записи — база встаёт со стороны курсора; маркер,
подпись и ховер-орбита рисуются по превью ещё до
подтверждения. Второй кнопкой — «Удалить базу»: запись уходит из хранилища
и из реестра (счётчик использований имени остаётся), карточка возвращается к
хозяину удалённой базы (планете или луне). Имена новых баз — случайные из `BASE_NAMES`
(`js/bases_name.js`, 100 названий); повтор выпадения получает суффикс
« - 2» по счётчику реестра имён — отдельного ключа localStorage
`galaxy_space_base_names_v1`, где по id имени хранятся текст, число
использований и список баз с местами (kind/planet/moon); реестр
синхронизируется при загрузке и после переноса базы. Стартовая база
LUNA-ORBIT — фикстура из data.js/render.js:
не переносится и в списке хранилища не участвует.

### Малые тела (smallbodies.js)
Главный пояс (частицы, щели Кирквуда, крупнейшие тела), ОЗА (Атон/Аполлон/
Амур), троянцы Юпитера L4/L5 с либрацией, кометы и пыль Койпера/Оорта. Каждое
тело — сущность со своим kind и id: генерация детерминированная (сидированный
ПСЧ) и выполняется при каждом запуске — пояс стабилен между загрузками, а
уничтоженные тела можно будет исключать по id (задел под добычу). Позиции
считаются каждый кадр из общего `simDays` через Кеплер (`keplerPos`), элементы
орбит реальные (a, e, долгота перигелия), карта — 2D-плоскость эклиптики.
Именованные тела — полноценные цели выбора, как планеты: в hoverTargets у них
поле `small`, в карточке — параметры орбиты и источника. Кометы рисуют ядро,
кому и хвост в экранных пикселях, всегда направленный от Солнца (длиннее и
ярче у перигелия). Пыль Койпера и Оорта не выбирается и отбрасывается по
полудиагонали кадра (полоса — целиком), точки — прямоугольниками ≥1.1 px.

### Блок «03 Малые тела» и полёт камеры
Строки-группы (`SMALL_ROWS`, ui.js): главный пояс, ОЗА, троянцы, кометы,
Койпер, Оорт и две метеоритные строки (тип `met`, акцентный цвет): «Марсианские
метеориты ≈300» и «Лунные метеориты ≈500» — ведут к Марсу и Луне (те же
строки-акценты есть в их карточках). Клик по строке — плавный полёт камеры
(`flyToCamera`) и выбор представителя (Церера / Эрос / Гектор / Галлея);
у Койпера и Оорта выбора нет — камера просто отъезжает показать кольцо.
Полёт — твин в `state.fly` по реальному времени (performance.now, а не
`state.time`, который масштабируется кнопками скорости): easeInOutCubic,
зум — геометрическая интерполяция, кламп MIN/MAX_ZOOM. Продвигает его
`updateFlyTo()` из кадрового цикла (main.js) до отрисовки мира; любой жест —
колесо, панорамирование, тач, клик по карте — полёт отменяет (input.js).
Факт-строка под списком: орбиты метеоритов Innisfree, Lost City, Příbram
прослежены до пояса.

### Дальний фон (sky.js) — отдельный слой
Небо рисуется независимо от игры: без участия `simDays`; слой сам знает про
камеру и зум, но игровую логику не трогает. Две части:

1. **Глубокое небо** — полоса Млечного Пути под ~60° к эклиптике (как наклон
   галактической плоскости в реальности), тёмная пылевая полоса, цветные
   туманности, галактика Андромеды, Магеллановы облака, звёздная пыль полосы
   и яркие звёзды. Собирается один раз в offscreen-canvas с запасом
   `OVERSCAN` по краям и блитится со смещением и масштабом: при
   панорамировании небо смещается на ~4% пути мира (`PARALLAX_K`) с
   насыщением на `MAX_SHIFT` — панорама бесконечна, кэш конечен, края
   никогда не оголяются; при зуме масштаб неба мягко растёт (`ZOOM_K` на
   каждое удвоение).
2. **Звёзды галактики** — два бесконечных тайлящихся слоя (тайл размером с
   экран, обёртка mod): дальний (k = 0.10) и средний (k = 0.35), мерцают.
   `k` — доля экранного пути мира, которую проходит слой (мир = 1.0).
   Существующие звёзды мира в `scene.js` — ближний слой (k = 1.0).

Позиции объектов полосы — в координатах полосы (u вдоль, v поперёк, доли
`L = hypot(W, H)`). Все параметры — константы в начале `sky.js`. Вызывается
из `render.js` до мировой системы координат (одна строка, `drawSky`).
Правки неба не затрагивают код солнца, планет, астероидов и симуляции
времени — и наоборот.

## Управление
- колесо мыши / pinch — зум (к курсору / середине между пальцами)
- правая кнопка мыши / перетаскивание тачем — панорамирование
- курсор — hover: название тела + его орбита; над выбираемыми объектами — указатель
- клик по солнцу / планете / луне / базе / малому телу — выбор: блок «Объект»
- клик по строке блока «03 Малые тела» — полёт камеры и выбор представителя
  группы (Койпер/Оорт — только полёт); любой жест отменяет полёт
- «Создать базу» / «Переместить базу» в карточке — выбор орбиты курсором
  (орбита переезжает к ближайшему телу); клик — применить, Esc / правая кнопка — отмена
- кнопки внизу — скорость времени (Медленнее / Нормально / Быстрее)
- клик по шапке блока — свернуть/развернуть

## Типичные правки
- Добавить луну → `data.js moonsByPlanet` (появится сама при зуме)
- Добавить планету → `data.js planets` (+ moonTree/moonTotals для панели)
- Поменять цвета/толщины → `config.js`
- Поменять правило раскрытия лун → `scene.js visibleMoons`
- Логика орбиты при наведении → `hover.js`
- Пояс астероидов (плотность, разброс радиусов) → `scene.js asteroids`
- Малые тела: состав пояса/ОЗА/троянцев/комет → `data.js`, поведение и
  генерация → `js/smallbodies.js`
- Строки блока «03 Малые тела» и метеоритные строки → `ui.js SMALL_ROWS`
- Полёт камеры (длительность, кривая) → `ui.js flyToCamera/updateFlyTo`
- Звёздные базы игрока: хранение, создание, перенос → `js/bases.js`,
  правило ближайшего тела → `input.js updateBaseRadius`;
  имена баз (BASE_NAMES) и реестр повторов → `js/bases_name.js` + `bases.js`
- Дальний фон: Млечный Путь, Андромеда, туманности → `js/sky.js`
- Список купленных кораблей базы → `ui.js baseInfoHTML/shipRowHTML`

# space/ — Солнечная система (интерактивная карта)

Карта солнечной системы на чистом canvas 2D. Без сборщиков и зависимостей:
ES-модули, раздаются любым статическим сервером. Тест локально:

```
cd C:\work\GalaxyAdminPanel
py -m http.server 8642
# http://127.0.0.1:8642/space/index.html
```

Стиль интерфейса — общий с ангаром (`hangar/`): стеклянные панели, IBM Plex
Mono для служебных подписей, бирюзово-фиолетовые акценты; модальные окна —
как ангарные `.slot-modal`/`.slot-dialog` (в `js/ui.js` — `confirmDialog`).
Общее правило стиля записано в корневом `AGENTS.md`.

## Зависимости между модулями (кто кого импортирует)

```
main ────► state, config, input, render, hover, ui
render ──► state, math, config, data, scene, sky, smallbodies, bases, iso, paint
hover ───► state, math, config, iso
input ───► state, math, config, data, hover, ui, bases, iso
ui ──────► state, math, data, config, bases (+ window.Store / window.Icons из data/)
smallbodies ─► state, math, data, config, iso, paint
bases ───► state, math, config, data, bases_name, bases_removed, iso, paint
scene ───► state
sky ─────► state
math ────► config, data
paint ───► math, config
iso ─────► config
data, config — ни от кого (чистые данные/константы)
```

Правило: config и data не импортируют ничего кроме друг друга (листья графа);
state знают все, но меняют его только input (камера/зум, режим базы),
ui (режим базы, полёт камеры) и main (время). Циклов нет: input зависит от ui
(выбор и карточка), ui от input — нет; полёт камеры поэтому живёт в ui.js.

## Ключевые концепции

### Время и орбиты — один таймер
`state.simDays` — сутки (дробные) от эпохи J2000. Планеты движутся по
уравнению Кеплера с реальными `e`/`peri` (`math.js keplerPos`), малые тела — по
своим элементам, луны — по реальным периодам и сжатым большим полуосям.
Поэтому счётчик дней, дата и взаимные положения тел всегда согласованы.
Симуляция стартует с реальной текущей даты. `timeScale` (кнопки внизу)
умножает скорость: x2/деление, пределы из config. Пояс астероидов живёт по
тому же таймеру: радиус 270–350, период по закону Кеплера от якорей
Марс → Юпитер; позиции каждый кадр считает `smallbodies.js`.

### Система координат: raw и view
Есть две плоскости:

- **raw** — эклиптика: солнце в (0,0), радиусы, углы, коридоры баз. Физика,
  `planet.dist`, `keplerPos3`, `orbitPoint3`, `rawDist`, `rawAngle` живут здесь.
- **view** — та же плоскость в диметрии 2:1: `y *= ISO_K` (0.5), а высота
  `z` над эклиптикой проецируется как `y -= z * ISO_Z` (0.866). Сюда
  переводятся позиции всех тел (`iso.js project3`), здесь работают камера,
  hover-цели, подписи, тени и маркеры баз.

`state.camX/camY` — точка view в центре экрана, `zoom` — масштаб; поэтому
`screenToWorld` не менялся. Обратный перевод для радиуса/угла базы:
`iso.js rawDist(dx, dy) = hypot(dx, dy/ISO_K)` и
`rawAngle = atan2(-(dy/ISO_K), dx)`. Смешивать raw и view в одном расчёте
нельзя: орбиты рисуются полилиниями по 3D-точкам, а сферы остаются круглыми.
Наклон орбит задаётся реальными `inc`/`node`: у планет, лун, крупных малых тел
и комет положение считается `keplerPos3`/`orbitPoint3` и проецируется
`project3`. Поэтому орбита планеты — не плоский эллипс, а наклонённая петля;
тень при этом остаётся на полу под телом (`floorY`).

### Зум и слипание тел по экранному расстоянию
Зум 0.3x–20x (`config.js`). Показанных тел кадра не «сколько-то по шкале
зума», а столько, сколько расходится на экране: при отдалении тела слипаются
в одно. Правило — `scene.js clusterBodies(bodies, zoom)`: тело встаёт в группу
ближайшего представителя **той же системы** (`system`: имя планеты у планеты
и её лун, `null` у малых тел), если их точки ближе `MERGE_PX` (50 экранных
пикселей), иначе становится представителем. Планеты, луны, солнце и кометы —
якоря (`anchor`): видны всегда, в чужую группу не входят. Поэтому луна не
«прилипает» к пролетавшему астероиду, а кометы не пропадают.

У группы видно только тело-представителя, остальные скрыты:

- у представителя подпись в две строки: первая — имена всех тел группы через
  запятую (планеты — русским именем `p.ru`, малые тела — `ru`), вторая
  (цианом, цветом баз) — базы игрока на телах группы
  (`render.js drawGroupLabel`; у малых тел баз пока нет — вторая строка не
  появляется);
- подписываются все показанные тела, а не только группы: одинокая планета,
  луна или малое тело всегда имеет имя на карте (hover-подсказка остаётся
  дополнительной) — Меркурий, Венера и одиночные спутники не остаются
  безымянными;
- базы игрока на скрытых телах не пропадают: `render.js` кладёт им
  хост-позицию представителя, и `bases.js` рисует их вокруг группы; имена этих
  баз гасятся — `render.js` собирает их id в `quietIds`, и `drawBases` их не
  подписывает;
- база на видимой луне подписывается двумя строками: сверху имя спутника,
  снизу имя базы (`bases.js drawBaseMarker`).

Hover-целью группы остаётся только представитель; у лун, планет и комет цель
своя (они якоря). Малые тела: `smallbodies.js smallBodyList()` отдаёт позиции
именованных тел кадру, `drawSmallBody` рисует только показанных; безымянные
ОЗА, частицы пояса, облака троянцев и пыль дальних поясов в правило не входят
(их не выбирают).

#### Раскладка подписей (`scene.js placeLabel`)
Подписи кадра (подписи групп и имена баз) не накладываются друг на друга:
перед отрисовкой подпись спрашивает место у раскладки — `placeLabel(x, yTop,
w, h)` возвращает сдвиг по вертикали. Если коробка подписи пересекается с уже
поставленной, подпись сдвигается вверх/вниз шагами в строку, пока место не
найдётся (у базы вместе с именем едет строка спутника и полоска разбора).
Раскладка начинается заново каждый кадр (`render.js` зовёт `resetLabels()`),
порядок постановки — порядок отрисовки: сначала подписи групп, затем имена
баз. Если места нет совсем (16 шагов), подпись остаётся на месте — лучше
наложение, чем пропавшая подпись.

### Стиль карты
Солнце, планеты, луны и астероиды — объёмные сферы (`paint.js sphere`):
радиальный градиент с бликом в верхней левой части и тёмным краем. На полу
под ними — мягкие эллиптические тени. Комета — ядро, кома и два хвоста
(пылевой изогнутый, ионный прямой) от Солнца. База — бирюзовый ромб
`#35e8d8` с ножкой, тенью и пульсом. Градиенты здесь осознанное исключение из
«плоского» стиля ангара: это карта, а не интерфейс.

### Орбиты и подписи
Постоянных орбит планет и путей комет на карте нет. При наведении на планету,
луну, малое тело или базу рисуется её орбита (планета — вокруг Солнца, луна —
вокруг планеты, база — вокруг хоста; у Солнца и комет орбиты нет). Hover-орбита —
белый пунктир-«шнурок»: толщина `3 / zoom`, промежуток между пунктирами
`16 / zoom`, край — несколько слоёв мягкой обводки; выбранная орбита (луны,
малых тел, баз) остаётся бирюзовой. Вместе с hover-орбитой у тела показывается
вертикальная проекция до `floorY` — белая линия с затуханием к концам; у комет,
Солнца и баз её нет. Подписи всех показанных тел (солнце, планеты, луны, малые
тела), имена баз и полоска разбора удаляемой базы видны всегда; раскладка без
наложений (`scene.js placeLabel`). Каждый кадр render.js возвращает
`hoverTargets` (солнце, планеты, все луны, звёздные базы, именованные малые
тела и все кометы); hover.js проверяет попадание курсора (луны и малые тела
приоритетнее — они поверх) и рисует орбиту, проекцию и текстовую подсказку у
курсора — просто белый текст с тенью, без рамки. У малых тел орбита —
сэмплированная полилиния `poly`: эллипс-дескриптор врёт вне линейных зон
`auToDist` и на наклонной орбите.

### Особый случай: Земля
Луна Земли — такая же запись тела кадра, как луны планет (`render.js
EARTH_MOON`), только не из `moonsByPlanet`: у неё своя дистанция
(`moonDist`) и радиус (3). Как и остальные луны, это якорь: видна всегда и не
слипается с Землёй. Базы на её орбите — обычные записи механизма баз
(bases.js), как у остальных лун.

### База: выбор и стартовая LUNA-ORBIT
База — полноценная цель выбора (`kind: 'base'` в hoverTargets): hover и клик
работают как у луны, пунктирная орбита — вокруг её хозяина. Стартовая база
игрока у Луны Земли раньше рисовалась жёстко (маркер «BASE» вне механизма);
теперь это обычная запись (`id` `base-luna-orbit`, флаг `fleet`): подчиняется
коридору и разведению, её можно перенести и удалить; если записи нет (первый
запуск после обновления), она создаётся миграцией при загрузке. В блоке
«Объект» (`ui.js`) такая база показывает свои параметры и список купленных
кораблей из общего хранилища проекта: `window.Store` (`data/store.js`, ключ
`galaxy_admin_db_v1`) и иконки `data/icons.js`. Строки — в формате списка
«В продаже» из ангара: иконка, имя, «Масса N кг», категория и цена покупки.
Если Store не подключён или список пуст — заметка вместо строк; без Store
страница работает как раньше (данные — необязательная зависимость, всё в
try/catch).

Кнопки карточки базы (`ui.js`): «Войти на базу» — переход в интерьер базы
(приложение ангара, `../hangar/index.html`), имя базы уходит в адрес
(`?base=…`), у разбираемой базы кнопка выключена; «Переместить базу» — режим
выбора орбиты; «Удалить базу» — подтверждение и разбор по таймеру.

### Звёздные базы игрока (bases.js)
Созданные игроком базы живут в отдельном ключе localStorage
(`galaxy_space_bases_v1`; данные админки/ангара не задействованы), прикреплены
к планете или луне и летают по круговой орбите радиуса `orbitRadius`. Период —
как у Луны: сутки на радиусе `baseOrbitRadius`, дальше по закону Кеплера.
Радиус зажат в коридор `baseRadiusRange` — от поверхности хозяина до
ближайшей чужой «полосы»: диск Солнца, полосы соседних планет (база у
Меркурия не дотягивается до орбиты Венеры, база у Венеры — до Меркурия и
Земли), у базы на планете — луны планеты (включая невидимые при зуме), у
базы на луне — планета под ней и луны-соседи по кольцам (`BASE_MAX_R` —
абсолютный потолок). Так орбита базы не пересекает ни тела, ни их орбиты;
если сосед слишком близко и коридор вырождается, база прижимается к
поверхности хозяина (запас `BASE_CLEAR` съедается). Вдобавок орбита
разводится с другими базами того же хозяина (`fitBaseRadius`, зазор
`BASE_SAME_GAP`): кольца не сливаются, а если свободного места нет — база
встаёт в точку с наибольшим зазором от чужих орбит. При загрузке радиусы
старых баз, созданных до появления полос и разведения, приводятся к коридору
и разводятся (в порядке массива; повторная загрузка ничего не двигает —
самовосстановление записи в хранилище). Здесь же миграция легаси: стартовой
базе «LUNA-ORBIT» создаётся обычная запись, если её ещё нет.
Создание: кнопка «Создать базу» в
карточке планеты/луны включает режим выбора орбиты (`state.baseMode`), радиус
следует за курсором, клик создаёт (Esc и правая кнопка отменяют). Сторона
орбиты — направление от центра хозяина к курсору (`mode.ang`): база и в
превью, и в записи встаёт с той стороны, куда указывает курсор (`phase0`
пересчитывается под этот угол, `phaseFor`). Правило
ближайшего тела: соседи (планеты и видимые луны) снимаются один раз при старте
режима (snapshot в `baseMode.snap`) — на движениях мыши позиции не
пересчитываются; как только точка орбиты оказывается дальше половины пути до
другого тела (курсор ближе к нему), орбита переезжает к нему: база у Венеры,
уведённая к Земле, станет базой Земли. У созданной базы в карточке есть
«Переместить базу» — тот же режим, но клик обновляет хост, радиус, период и
сторону (фазу) существующей записи — база встаёт со стороны курсора; маркер,
подпись и ховер-орбита рисуются по превью ещё до
подтверждения. Имя базы на карте — шрифтом интерфейса: Manrope 600, как
`.b-name` в списках базы, кегль постоянный на экране (10 px; начертание
прогревается в `main.js`, canvas сам веб-шрифты не подгружает). Подпись живёт в невидимой «панели» фиксированной
ширины `BASE_LABEL_W` (96 экранных пикселей, без фона и рамки): что не
влезает — режется с «…», а при наведении на базу (маркер или саму панель)
включается бегущая строка — имя уезжает влево и его можно прочитать целиком.
Второй
кнопкой — «Удалить базу»: сначала диалог подтверждения
в общем стиле ангара (confirmDialog: тёмный фон, стеклянная панель, eyebrow,
«×» — как .slot-dialog), и только после согласия база уходит в статус
`removing` на `BASE_REMOVAL_MS` (4 с реального времени) — перенос и
повторное удаление недоступны, а имя базы на карте и в карточке краснеет
(общий красный) и под ним тянется полоска прогресса разбора — во всю панель,
справа налево (в списках базы тот же бар `.rm-bar` — тоже справа налево).
Когда время
вышло (`updateBaseRemovals` в кадре),
база исчезает с орбиты: запись получает статус `removed` (надгробие в
хранилище баз — отметка, что база удалена) и целиком уезжает в архив
`js/bases_removed.js`, а её место в реестре имён помечается `removed`
(счётчик использований имени остаётся). Если выбранная база доудалилась,
карточка сама возвращается к её хозяину. Имена новых баз — случайные из `BASE_NAMES`
(`js/bases_name.js`, 100 названий); повтор выпадения получает суффикс
« - 2» по счётчику реестра имён — отдельного ключа localStorage
`galaxy_space_base_names_v1`, где по id имени хранятся текст, число
использований и список баз с местами (kind/planet/moon) и статусами; реестр
синхронизируется при загрузке и после переноса базы. Стартовая база
LUNA-ORBIT (id `base-luna-orbit`, флаг `fleet`) — обычная запись механизма;
`nameId` у неё нет, в реестре имён она не участвует.

#### Таблицы хранилища баз (localStorage)
Три ключа, обособленных от данных админки/ангара. Статус базы (`status`):
`active` — работает; `removing` — удаляется, идёт таймер; `removed` —
удалена (надгробие: на карте не рисуется, в списках не показывается).

**`galaxy_space_bases_v1` — базы (пишет bases.js):**

| Поле | Тип | Описание |
| --- | --- | --- |
| `id` | строка | уникальный (`base-<время>-<номер>`; у LUNA-ORBIT — `base-luna-orbit`) |
| `name` | строка | имя из `BASE_NAMES`, у повторов с суффиксом « - N» |
| `nameId` | число | индекс имени в `BASE_NAMES` (bases_name.js) |
| `nameCount` | число | номер использования имени на момент создания |
| `status` | строка | `active` / `removing` / `removed` |
| `hostKind` | строка | `planet` или `moon` — к чему прикреплена |
| `planet` | строка | планета-хозяин |
| `moon` | строка или null | луна-хозяин |
| `orbitRadius` | число | радиус орбиты (единицы мира; коридор хозяина + разведение с его базами) |
| `period` | число | период обращения, суток |
| `phase0` | число | фаза орбиты, радианы |
| `created` | ISO-строка | когда создана |
| `fleet` | булево | необязательно: стартовая база игрока — в карточке купленные корабли (LUNA-ORBIT) |
| `removeEndsAt` | число | только `removing`: конец разбора, мс `Date.now()` |
| `removedAt` | ISO-строка | только `removed`: когда разбор закончился |
| `x`, `y` | число | только в памяти: позиция на карте (каждый кадр) |

**`galaxy_space_base_names_v1` — реестр имён (пишет bases.js):**

`{ v: 1, names: { '<nameId>': { id, name, count, bases[] } } }`

| Поле | Тип | Описание |
| --- | --- | --- |
| `id` | число | индекс имени в `BASE_NAMES` |
| `name` | строка | само название, без суффикса |
| `count` | число | сколько раз имя выпадало (для суффикса; не сбрасывается) |
| `bases[]` | массив | где стоят базы с этим именем |
| `bases[].baseId` | строка | `id` базы |
| `bases[].name` | строка | полное имя базы (с суффиксом) |
| `bases[].kind`, `planet`, `moon` | строка | место базы |
| `bases[].status` | строка | статус базы (запись остаётся отметкой и после удаления) |

**`galaxy_space_bases_removed_v1` — архив удалённых (пишет bases_removed.js):**

Массив полных копий записей на момент конца разбора: все поля базы выше,
плюс `status: 'removed'` и `removedAt` (и `x`/`y` на момент удаления).

### Малые тела (smallbodies.js)
Главный пояс (частицы, щели Кирквуда, крупнейшие тела), ОЗА (Атон/Аполлон/
Амур), троянцы Юпитера L4/L5 с либрацией, кометы и пыль Койпера/Оорта. Каждое
тело — сущность со своим kind и id: генерация детерминированная (сидированный
ПСЧ) и выполняется при каждом запуске — пояс стабилен между загрузками, а
уничтоженные тела можно будет исключать по id (задел под добычу). Позиции
считаются каждый кадр из общего `simDays` через Кеплер (`keplerPos3`), элементы
орбит реальные (a, e, долгота перигелия, наклонение inc и узел node), карта
проецирует 3D-точки в диметрию (`project3`).
Именованные тела — полноценные цели выбора, как планеты: в hoverTargets у них
поле `small`, в карточке — параметры орбиты и источника. При отдалении
именованные тела слипаются общим правилом (`clusterBodies`, см. выше):
`smallBodyList()` считает их позиции каждый кадр, точками рисуются только
показанные (представители групп), остальные схлопываются в подпись-список;
безымянные досыпанные ОЗА всегда рисуются тусклыми точками и в правило не
входят. Кометы рисуют ядро, кому и хвост в экранных пикселях,
всегда направленный от Солнца (длиннее и ярче у перигелия). Пыль Койпера и
Оорта не выбирается и отбрасывается по полудиагонали кадра (полоса —
целиком), точки — прямоугольниками ≥1.1 px.

### Блок «03 Малые тела» и полёт камеры
Строки-группы (`SMALL_ROWS`, ui.js): главный пояс, ОЗА, троянцы, кометы,
Койпер, Оорт и две метеоритные строки (тип `met`, акцентный цвет): «Марсианские
метеориты ≈300» и «Лунные метеориты ≈500» — ведут к Марсу и Луне (те же
строки-акценты есть в их карточках). Клик по строке — плавный полёт камеры
(`flyToCamera`) и выбор представителя (Церера / Эрос / Гектор / Галлея);
у Койпера и Оорта выбора нет — камера просто отъезжает показать кольцо.
Полёт — твин в `state.fly` по реальному времени (performance.now, а не
`state.time`, который масштабируется кнопками скорости): easeInOutCubic,
зум — геометрическая интерполяция, кламп MIN/MAX_ZOOM. Продвигает его
`updateFlyTo()` из кадрового цикла (main.js) до отрисовки мира; любой жест —
колесо, панорамирование, тач, клик по карте — полёт отменяет (input.js).
Факт-строка под списком: орбиты метеоритов Innisfree, Lost City, Příbram
прослежены до пояса.

### Дальний фон (sky.js) — отдельный слой
Небо рисуется независимо от игры: без участия `simDays`; слой сам знает про
камеру и зум, но игровую логику не трогает. Две части:

1. **Глубокое небо** — полоса Млечного Пути под ~60° к эклиптике (как наклон
   галактической плоскости в реальности), тёмная пылевая полоса, цветные
   туманности, галактика Андромеды, Магеллановы облака, звёздная пыль полосы
   и яркие звёзды. Собирается один раз в offscreen-canvas с запасом
   `OVERSCAN` по краям и блитится со смещением и масштабом: при
   панорамировании небо смещается на ~4% пути мира (`PARALLAX_K`) с
   насыщением на `MAX_SHIFT` — панорама бесконечна, кэш конечен, края
   никогда не оголяются; при зуме масштаб неба мягко растёт (`ZOOM_K` на
   каждое удвоение).
2. **Звёзды галактики** — два бесконечных тайлящихся слоя (тайл размером с
   экран, обёртка mod): дальний (k = 0.10) и средний (k = 0.35), мерцают.
   `k` — доля экранного пути мира, которую проходит слой (мир = 1.0).
   Существующие звёзды мира в `scene.js` — ближний слой (k = 1.0).

Позиции объектов полосы — в координатах полосы (u вдоль, v поперёк, доли
`L = hypot(W, H)`). Все параметры — константы в начале `sky.js`. Вызывается
из `render.js` до мировой системы координат (одна строка, `drawSky`).
Правки неба не затрагивают код солнца, планет, астероидов и симуляции
времени — и наоборот.

## Управление
- колесо мыши / pinch — зум (к курсору / середине между пальцами)
- правая кнопка мыши / перетаскивание тачем — панорамирование
- курсор — hover: название тела, белая орбита-«шнурок» и вертикальная проекция;
  над выбираемыми объектами — указатель
- клик по солнцу / планете / луне / базе / малому телу — выбор: блок «Объект»
- клик по строке блока «03 Малые тела» — полёт камеры и выбор представителя
  группы (Койпер/Оорт — только полёт); любой жест отменяет полёт
- «Создать базу» / «Переместить базу» в карточке — выбор орбиты курсором
  (орбита переезжает к ближайшему телу); клик — применить, Esc / правая кнопка — отмена
- «Войти на базу» в карточке базы — переход в интерьер базы (приложение ангара)
- кнопки внизу — скорость времени (Медленнее / Нормально / Быстрее)
- клик по шапке блока — свернуть/развернуть

## Типичные правки
- Добавить луну → `data.js moonsByPlanet` (появится сама при зуме)
- Добавить планету → `data.js planets` (+ moonTree/moonTotals для панели)
- Поменять цвета/толщины → `config.js`
- Поменять порог слипания тел → `scene.js MERGE_PX` (экранные пиксели: тела
  ближе порога слипаются в группу при текущем зуме)
- Слипание тел и раскладка подписей → `scene.js clusterBodies`/`placeLabel`
  (+ `render.js` — тела кадра, подписи групп, `hostPos`/`quietIds`; базы и
  малые тела — `bases.js drawBases`, `smallbodies.js smallBodyList`/
  `drawSmallBodies`); имя спутника в подписи базы на видимой луне —
  `bases.js drawBaseMarker` (строка выше имени)
- Логика орбиты при наведении → `hover.js`
- Пояс астероидов (плотность, разброс радиусов) → `js/smallbodies.js`
- Малые тела: состав пояса/ОЗА/троянцев/комет → `data.js`, поведение и
  генерация → `js/smallbodies.js`
- Строки блока «03 Малые тела» и метеоритные строки → `ui.js SMALL_ROWS`
- Полёт камеры (длительность, кривая) → `ui.js flyToCamera/updateFlyTo`
- Звёздные базы игрока: хранение, создание, перенос → `js/bases.js`,
  правило ближайшего тела → `input.js updateBaseRadius`;
  имена баз (BASE_NAMES) и реестр повторов → `js/bases_name.js` + `bases.js`
- Коридор радиуса орбиты базы (Солнце, соседние планеты, луны-соседи,
  самовосстановление старых баз) → `bases.js baseRadiusRange`
- Удаление баз (таймер, статусы, архив) → `js/bases.js` (`BASE_REMOVAL_MS`,
  `startBaseRemoval`/`updateBaseRemovals`) + `js/bases_removed.js`;
  диалог подтверждения → `js/ui.js` (`confirmDialog`, стили `.dlg-*` в
  `css/style.css`)
- Подпись базы на карте (панель фиксированной ширины, бегущая строка при
  наведении, полоска разбора справа налево) → `bases.js` (`BASE_LABEL_W`,
  `drawBaseMarker`); бар в списках — `.rm-bar` в `css/style.css`
- Дальний фон: Млечный Путь, Андромеда, туманности → `js/sky.js`
- Список купленных кораблей базы → `ui.js baseInfoHTML/shipRowHTML`

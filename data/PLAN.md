# data/ — план и требования

Рабочий план приведения слоя данных к правилам `data/RULES.md`:
**этап 1** — покупка на корабль в ангаре, трюмы, контейнеры, `prop_2`, масса
(§ 1–8, закрыт); **этап 2** — продажа оборудования и ресурсов с корабля
(§ 9–15).

Файл — точка входа для следующей сессии. Если что-то здесь расходится с
`RULES.md`, правы правила, а план надо поправить.

## 1. Цель этапа

- Игрок покупает в ангаре оборудование и ресурсы **на конкретный корабль**.
- Покупка уважает крепления, трюмы, контейнеры и массу.
- Каждый купленный корабль имеет **свой** набор оборудования.
- Данные (админка) позволяют всё это задать: `prop_2`, трюмы корабля.

Не входит в этап: объём, энергия/охлаждение/экипаж, крафт, добыча, поле
количества при покупке (см. § 8). Продажа — отдельный этап 2 (§ 9–15).

## 2. Что уже сделано (не переделывать)

Слой данных, покупка и ангар готовы — шаги 1–8 закрыты:

- Ресурсы без массы; единица ресурса = единица груза (`Store.cargoUnits`).
- `prop_2` у объектов: массив материалов, «0» и пусто — не задано. Поле есть
  в форме объекта и в таблице; варианты — названия ресурсов каталога.
- Трюмы у корабля (`ship.holds`): название, вместимость, содержимое; редактор
  в форме корабля. Шаблоны «Трюм 1/5/10 т» убраны, прежние грузовые слоты
  при загрузке становятся трюмами.
- У записи купленного корабля (`users_ships`) свои `slots` и `holds`;
  `buyShip` копирует пустую раскладку каталога, старые записи получают её
  при санитизации.
- Масса рекурсивная: `Store.contentsMass`, `cargoMass`, `shipMass`,
  `holdFree`, `containerFree`. `usedMass` — то же, что `contentsMass`.
- Демо: четыре ресурса, отсеки и баки с `prop_2`, трюмы у кораблей.
- Покупка на корабль: `Store.buyForShip` (крепление → трюм → отказ;
  ресурс → подходящий контейнер → отказ). В ангаре отказ показывается
  модалкой с причиной, успех — в строке состояния.
- Ангар читает раскладку записи: крепления, трюмы, реальное оборудование,
  масса корабля. Клик по пустому креплению открывает нужную подкатегорию.
- Список «В продаже» разбит на блоки по подкатегориям.
- Категории ищутся по всему поддереву (3+ уровня).

## 3. Схема данных

### Объект каталога

```js
{
  id, name, categoryId, parentCategoryId,
  values: { [propId]: 'значение' },   // prop_1: масса, скорость, вместимость…
  price_buy, price_sale, icon,
  slotId: 'id шаблона крепления' | null,  // null — в крепление не вставляется
  prop2: ['железо', 'медь'],              // НОВОЕ: материалы; пусто — []
  slots: []                                // у корабля-каталога — раскладка
}
```

### Корабль в каталоге

```js
{
  ...объект,
  slots: [{ slotId: 'крепление' }],                   // раскладка
  holds: [{ name: 'Трюм 1', capacity: '1000' }]       // НОВОЕ, вместимость в кг
}
```

### Купленный корабль (`users_ships`)

```js
{
  id, shipId, name, categoryId, price, boughtAt,
  slots: [{ slotId, contents: [entry] }],             // НОВОЕ: свой набор
  holds: [{ name, capacity, contents: [entry] }]      // НОВОЕ: свой набор
}
```

### Запись содержимого (`entry`)

```js
{ itemId: 'объект', qty: '1', cargo: [{ itemId: 'ресурс', qty: '120' }] }
```

- `cargo` — содержимое контейнера (только у контейнеров), в кг;
- оборудование в трюме может иметь `qty > 1` (одинаковые предметы);
- контейнер всегда `qty = 1` — у каждого своё содержимое.

## 4. Алгоритмы

```js
entryMass(entry)       = massOf(item) * qty                 // оборудование
entryCargoMass(entry)  = Σ 1 * qty по entry.cargo           // ресурс: 1 кг = 1
shipMass(ship)         = massOf(ship) + Σ entryMass + Σ entryCargoMass

holdFree(hold)         = hold.capacity - Σ entryMass(hold.contents)
containerFree(entry)   = capacityOf(entry.item) - entryCargoMass(entry)
```

`holdFree` не учитывает груз в контейнерах — у контейнера своя вместимость.

### Покупка

```
buyForShip(record, objectId, qty = 1):
  цена = priceBuy(object) * qty
  если кредитов < цена            → отказ «Недостаточно кредитов»

  если object — ресурс:
      контейнер = первый в record.slots и record.holds, где
                  prop2 контейнера содержит имя ресурса
                  и containerFree >= qty
      если нет                    → отказ «Нет подходящего грузового отсека»
      иначе cargo += qty (кг)

  иначе (оборудование):
      крепление = первое в record.slots, где slotId === object.slotId
                  и contents пусто
      если есть                   → contents = [entry]
      иначе:
          трюм = первый в record.holds, где holdFree >= massOf(object) * qty
          если есть               → contents.push(entry)
          иначе                   → отказ «Нет свободного крепления и места в трюме»

  списать кредиты, сохранить
```

Отказ — **модальным окном** с причиной; успех — строкой в консоли терминала.

## Этап 2. Продажа

### 9. Цель и границы

- Игрок продаёт оборудование и ресурсы **с конкретного купленного корабля**.
- Цена — `price_sale` за штуку или за килограмм; пусто → `price_buy`,
  ноль → отказ.
- Деньги сразу на баланс, предмет исчезает; склада базы нет.
- Проданное освобождает крепление, место в трюме или в контейнере; масса
  корабля уменьшается.
- Колонка «На корабле» в магазине показывает реальный груз выбранного корабля.
- Одна продажа = 1 шт. или 1 кг; поле количества — отдельный этап (§ 15).

Не входит: склад базы, выгрузка на базу, комиссии, аукцион, продажа корабля
без содержимого.

### 10. Схема данных

Новых коллекций нет: продажа работает с той же записью `users_ships`.

```js
{
  slots: [{ slotId, contents: [entry] }],
  holds: [{ name, capacity, contents: [entry] }]
}
```

Адрес продажи:

```js
{ kind: 'slot' | 'hold', index, entry, cargo? }
```

- `index` — позиция в `record.slots` / `record.holds`;
- `entry` — индекс в `contents`;
- `cargo` — индекс строки в `entry.cargo` (ресурс из контейнера);
  без `cargo` — сам предмет.

Стоимость: за единицу `priceSale(item)`, за килограмм `priceSale(resource)`.

### 11. Алгоритмы

```js
entryValue(entry)   = priceSale(item) * qty           // оборудование
cargoValue(entry)   = Σ priceSale(ресурс) * кг        // груз контейнера
shipSaleValue(rec)  = priceSale(корабль) + Σ entryValue + Σ cargoValue
```

```js
sellEntry(recordId, place, entryIndex, withCargo):
  запись, позиция и entry существуют      иначе отказ
  item = entry.itemId
  если это контейнер и в нём есть груз:
      без withCargo → отказ «В контейнере есть груз»
      цена = priceSale(item) + cargoValue(entry)
  иначе цена = priceSale(item)            // одна штука
  цена <= 0                               → отказ «Цена продажи не задана»

  qty = qty - 1; если 0 — удалить entry из contents
  кредиты += цена; сохранить
```

```js
sellCargo(recordId, place, entryIndex, cargoIndex):
  строка груза существует                 иначе отказ
  цена = priceSale(ресурс); 0             → отказ
  кг = кг - 1; если 0 — удалить строку
  кредиты += цена; сохранить
```

```js
sellResource(recordId, resourceId):       // колонка «На корабле»
  первый контейнер (slots, затем holds), где в cargo есть ресурс
  нет                                     → отказ «На корабле нет такого ресурса»
  иначе sellCargo(…, 1)                   // 1 кг
```

```js
sellShip(recordId):
  total = shipSaleValue(record)
  total <= 0                              → отказ «Цена продажи не задана»
  удалить запись; кредиты += total
  вернуть { price, shipPrice, gearPrice, cargoPrice, credits }
```

#### Шаг 13. Проверка — [ ]

1. Продать лазер из крепления → крепление свободно, кредиты +цена, масса −масса.
2. Продать предмет из стопки в трюме → qty −1; последний — строка исчезает.
3. Продать 1 кг железа → кг −1, масса −1.
4. Контейнер с грузом: «вместе с грузом» → уходят оба, кредиты = контейнер +
   груз; «Отмена» ничего не меняет.
5. Продать ресурс из «На корабле» → уходит из первого контейнера, где он есть.
6. Продать корабль с оборудованием и грузом → сумма = корабль + содержимое,
   запись удалена.
7. Цена продажи 0 → отказ модалкой с причиной.

### 13. Решения по умолчанию

- Одна продажа = одна штука или один килограмм.
- Деньги сразу на баланс, без комиссии; проданное не хранится на базе.
- Цена: `price_sale`, пусто — `price_buy`, ноль — отказ.
- Контейнер с грузом — только вместе с грузом, по подтверждению; по строкам
  груз продаётся отдельно.
- Корабль всегда продаётся вместе с содержимым, по подтверждению.
- Округление: до целого ¤ по строке; итог — сумма строк.
- Продажа только с записи `users_ships`; статичные списки в расчёте не участвуют.

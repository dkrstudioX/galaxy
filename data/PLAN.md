# data/ — план и требования

Рабочий план приведения слоя данных к правилам `data/RULES.md`:
**этап 1** — покупка на корабль в ангаре, трюмы, контейнеры, `prop_2`, масса
(§ 1–8, закрыт); **этап 2** — продажа оборудования и ресурсов с корабля
(§ 9–15).

Файл — точка входа для следующей сессии. Если что-то здесь расходится с
`RULES.md`, правы правила, а план надо поправить.

## 1. Цель этапа

- Игрок покупает в ангаре оборудование и ресурсы **на конкретный корабль**.
- Покупка уважает крепления, трюмы, контейнеры и массу.
- Каждый купленный корабль имеет **свой** набор оборудования.
- Данные (админка) позволяют всё это задать: `prop_2`, трюмы корабля.

Не входит в этап: объём, энергия/охлаждение/экипаж, крафт, добыча, поле
количества при покупке (см. § 8). Продажа — отдельный этап 2 (§ 9–15).

## 2. Что уже сделано (не переделывать)

Слой данных, покупка и ангар готовы — шаги 1–8 закрыты:

- Ресурсы без массы; единица ресурса = единица груза (`Store.cargoUnits`).
- `prop_2` у объектов: массив материалов, «0» и пусто — не задано. Поле есть

- Трюмы у корабля (`ship.holds`): название, вместимость, содержимое; редактор
  в форме корабля. Шаблоны «Трюм 1/5/10 т» убраны, прежние грузовые слоты
  при загрузке становятся трюмами.
- У записи купленного корабля (`users_ships`) свои `slots` и `holds`;
  `buyShip` копирует пустую раскладку каталога, старые записи получают её
  при санитизации.
- Масса рекурсивная: `Store.contentsMass`, `cargoMass`, `shipMass`,
  `holdFree`, `containerFree`. `usedMass` — то же, что `contentsMass`.
- Демо: четыре ресурса, отсеки и баки с `prop_2`, трюмы у кораблей.
- Покупка на корабль: `Store.buyForShip` (крепление → трюм → отказ;
  ресурс → подходящий контейнер → отказ). В ангаре отказ показывается
  модалкой с причиной, успех — в строке состояния.
- Ангар читает раскладку записи: крепления, трюмы, реальное оборудование,
  масса корабля. Содержимое трюма — квадратами, как слоты; подробности
  предмета (категория, масса, груз контейнера) — в подсказке при наведении.
- Колонка «На корабле» в магазине — реальное оборудование записи: каждый
  предмет отдельно, строки как в витрине; фильтр по категории/подкатегории
  общий с «В продаже», клик по строке выбирает предмет и показывает в консоли
  место, массу и цену продажи.
- Одинаковые предметы не складываются: каждая покупка — отдельная запись
  (`qty = 1`), у контейнера свой груз.
- Список «В продаже» разбит на блоки по подкатегориям.
- Категории ищутся по всему поддереву (3+ уровня).

## 3. Схема данных

### Объект каталога

```js
{
  id, name, categoryId, parentCategoryId,
  values: { [propId]: 'значение' },   // prop_1: масса, скорость, вместимость…
  price_buy, price_sale, icon,
  slotId: 'id шаблона крепления' | null,  // null — в крепление не вставляется
  prop2: ['железо', 'медь'],              // НОВОЕ: материалы; пусто — []
  slots: []                                // у корабля-каталога — раскладка
}
```

### Корабль в каталоге

```js
{
  ...объект,
  slots: [{ slotId: 'крепление' }],                   // раскладка
  holds: [{ name: 'Трюм 1', capacity: '1000' }]       // НОВОЕ, вместимость в кг
}
```

### Купленный корабль (`users_ships`)

```js
{
  id, shipId, name, categoryId, price, boughtAt,
  slots: [{ slotId, contents: [entry] }],             // НОВОЕ: свой набор
  holds: [{ name, capacity, contents: [entry] }]      // НОВОЕ: свой набор
}
```

### Запись содержимого (`entry`)

```js
{ itemId: 'объект', qty: '1', cargo: [{ itemId: 'ресурс', qty: '120' }] }
```

- `cargo` — содержимое контейнера (только у контейнеров), в кг;
- каждый предмет — отдельная запись, `qty` всегда `1`: две одинаковые пушки
  после покупки — два разных предмета;
- контейнер тоже всегда `qty = 1` — у каждого своё содержимое.

## 4. Алгоритмы

```js
entryMass(entry)       = massOf(item) * qty                 // оборудование
entryCargoMass(entry)  = Σ 1 * qty по entry.cargo           // ресурс: 1 кг = 1
shipMass(ship)         = massOf(ship) + Σ entryMass + Σ entryCargoMass

holdFree(hold)         = hold.capacity - Σ entryMass(hold.contents)
containerFree(entry)   = capacityOf(entry.item) - entryCargoMass(entry)
```

`holdFree` не учитывает груз в контейнерах — у контейнера своя вместимость.

### Покупка

```
buyForShip(record, objectId, qty = 1):
  цена = priceBuy(object) * qty
  если кредитов < цена            → отказ «Недостаточно кредитов»

  если object — ресурс:
      контейнер = первый в record.slots и record.holds, где
                  prop2 контейнера содержит имя ресурса
                  и containerFree >= qty
      если нет                    → отказ «Нет подходящего грузового отсека»
      иначе cargo += qty (кг)

  иначе (оборудование):
      крепление = первое в record.slots, где slotId === object.slotId
                  и contents пусто
      если есть                   → contents = [entry]
      иначе:
          трюм = первый в record.holds, где holdFree >= massOf(object) * qty
          если есть               → contents.push(entry)   // отдельная запись
          иначе                   → отказ «Нет свободного крепления и места в трюме»

  списать кредиты, сохранить
```

Отказ — **модальным окном** с причиной; успех — строкой в консоли терминала.

## Этап 2. Продажа

### 9. Цель и границы

- Игрок продаёт оборудование и ресурсы **с конкретного купленного корабля**.
- Цена — `price_sale` за штуку или за килограмм; пусто → `price_buy`,
  ноль → отказ.
- Деньги сразу на баланс, предмет исчезает; склада базы нет.
- Проданное освобождает крепление, место в трюме или в контейнере; масса
  корабля уменьшается.
- Колонка «На корабле» в магазине показывает реальный груз выбранного корабля.
- Одна продажа = 1 шт. или 1 кг; поле количества — отдельный этап (§ 15).

Не входит: склад базы, выгрузка на базу, комиссии, аукцион, продажа корабля
без содержимого.

### 10. Схема данных

Новых коллекций нет: продажа работает с той же записью `users_ships`.

```js
{
  slots: [{ slotId, contents: [entry] }],
  holds: [{ name, capacity, contents: [entry] }]
}
```

Адрес продажи:

```js
{ kind: 'slot' | 'hold', index, entry, cargo? }
```

- `index` — позиция в `record.slots` / `record.holds`;
- `entry` — индекс в `contents`;
- `cargo` — индекс строки в `entry.cargo` (ресурс из контейнера);
  без `cargo` — сам предмет.

Стоимость: за единицу `priceSale(item)`, за килограмм `priceSale(resource)`.

### 11. Алгоритмы

```js
entryValue(entry)   = priceSale(item)                 // предмет всегда один
cargoValue(entry)   = Σ priceSale(ресурс) * кг        // груз контейнера
shipSaleValue(rec)  = priceSale(корабль) + Σ entryValue + Σ cargoValue
```

```js
sellEntry(recordId, place, entryIndex, withCargo):
  запись, позиция и entry существуют      иначе отказ
  item = entry.itemId
  если это контейнер и в нём есть груз:
      без withCargo → отказ «В контейнере есть груз»
      цена = priceSale(item) + cargoValue(entry)
  иначе цена = priceSale(item)            // одна штука
  цена <= 0                               → отказ «Цена продажи не задана»

  удалить entry из contents               // каждый предмет — отдельная запись
  кредиты += цена; сохранить
```

```js
sellCargo(recordId, place, entryIndex, cargoIndex):
  строка груза существует                 иначе отказ
  цена = priceSale(ресурс); 0             → отказ
  кг = кг - 1; если 0 — удалить строку
  кредиты += цена; сохранить
```

```js
sellResource(recordId, resourceId):       // колонка «На корабле»
  первый контейнер (slots, затем holds), где в cargo есть ресурс
  нет                                     → отказ «На корабле нет такого ресурса»
  иначе sellCargo(…, 1)                   // 1 кг
```

```js
sellShip(recordId):
  total = shipSaleValue(record)
  total <= 0                              → отказ «Цена продажи не задана»
  удалить запись; кредиты += total
  вернуть { price, shipPrice, gearPrice, cargoPrice, credits }
```

    `prop_2`, вместимость; те же стили, что у состава.

### 13. Решения по умолчанию

- Одна продажа = одна штука или один килограмм.
- Клик по заполненному слоту или квадрату трюма — это клик по оборудованию:
  выделяет строку только в «На корабле»; витрина при этом не выделяется,
  справа показывается карточка предмета с кнопкой «Продать». Модалка
  слота по клику не открывается; пустой слот — подбор совместимых товаров.
- У контейнера с грузом значки ресурсов кликабельны отдельно: выбор строки
  груза и продажа 1 кг; остальная часть квадрата выбирает сам контейнер.
- Одинаковые предметы не складываются: продажа убирает конкретную запись.
- Деньги сразу на баланс, без комиссии; проданное не хранится на базе.
- Цена: `price_sale`, пусто — `price_buy`, ноль — отказ.
- Контейнер с грузом — только вместе с грузом, по подтверждению; по строкам
  груз продаётся отдельно. В карточке контейнера — список груза: ресурс и кг,
  затем итог; кнопка «Продать вместе с грузом» под списком.
- В карточке товара-контейнера в магазине — блок «Можно положить»: материалы
  из `prop_2` и вместимость; те же стили, что у состава купленного контейнера.
- Корабль всегда продаётся вместе с содержимым, по подтверждению.
- Округление: до целого ¤ по строке; итог — сумма строк.
- Продажа только с записи `users_ships`; статичные списки в расчёте не участвуют.

### 14. Критерии готовности

- [x] Продажа из крепления, трюма и контейнера меняет запись и массу корабля.
- [x] Освободившееся крепление снова участвует в покупке.
- [x] Контейнер с грузом уходит только с подтверждением общей суммы.
- [x] «На корабле» показывает реальный груз выбранного корабля и продаёт его.
- [x] Продажа корабля возвращает стоимость содержимого.
- [x] Отказ — модалкой с причиной, успех — строкой в терминале.
- [x] Клик по заполненному слоту/трюму выделяет предмет в «На корабле».
- [x] Груз контейнера: значки в квадрате, подсказка, клик по значку и по
  контейнеру ведут к разным карточкам.
- [ ] `RULES.md` и код не противоречат друг другу.

### 15. Не делаем в этапе 2

- Склад базы, выгрузка на базу, хранение проданного.
- Поле количества при покупке и продаже.
- Комиссии, наценки, аукцион, торг.
- Продажу предметов, которых нет в записи корабля.

## 16. Категории: три группы (реализовано)

Цель: вернуть три равноправные группы — **Оборудование**, **Ресурсы**,
**Корабли** — в админке и магазине. В админке раздел «Каталог» получает три
пункта навигации: «Категории кораблей», «Категории ресурсов», «Категории
оборудования». В магазине после «Все» появляются три корневых таба, у
каждого — свои подкатегории.

### 16.1. Итоговое дерево

**Оборудование** — корень, `isShip = false`:

1. Лазеры — «Лазер M-1…M-10».
2. Пулемёты — «Пулемёт P-1…P-10».
3. Щиты — «Щит S-1…S-10».
4. Двигатели — «Двигатель E-1…E-4».
5. Радары и сканеры — «Радар R-1…R-4», «Сканер C-1…C-4».
6. Добывающее — «Бур D-1…D-5».
7. Переработка — «Переработчик R-1…R-5».
8. Грузовые отсеки — 500 кг, 2 т, 5 т, 10 т.
9. Топливные баки — 1 т, 5 т, 10 т.
10. Расходники — ремкомплект, набор запчастей, аптечка.

**Ресурсы** — корень, `isShip = false`:

1. Материалы — «Железо», «Медь», «Золото», «Камень».
2. Топливо — пока пусто, задел под топливо как ресурс.

**Корабли** — корень, `isShip = true`:

1. Линкоры — «Гром».
2. Фрегаты — «Сокол».
3. Корветы — «Оса».
4. Перехватчики — «Стриж».
5. Шаттлы — «Челнок».
6. Грузовозы — «Баржа».

Промежуточные группы «Оружие», «Защита», «Грузовые системы» не вводим:
магазин показывает один уровень подкатегорий. Порядок внутри групп — как
в списке выше.

### 16.2. Админка: три пункта навигации

- В разделе «Каталог» три отдельных пункта меню:
  **«Категории кораблей»**, **«Категории ресурсов»**, **«Категории
  оборудования»**. Каждый открывает общий экран категорий со своей группой.
  Вкладки внутри страницы не нужны: группа задаётся маршрутом.
- Маршруты: `#/categories/ships`, `#/categories/resources`,
  `#/categories/equipment`. Старый `#/categories` ведёт на корабли,
  `#/categories/goods` — на оборудование.
- Перед рендером на клиенте строится карта групп из Store:

  ```js
  {
    equipment: { title: 'Оборудование', root: { id: '…' }, items: [{ id: '…', title: 'Лазеры' }, …] },
    resources: { title: 'Ресурсы',     root: { id: '…' }, items: [{ id: '…', title: 'Материалы' }, …] },
    ships:     { title: 'Корабли',     root: { id: '…' }, items: [{ id: '…', title: 'Линкоры' }, …] }
  }
  ```

  `id` — реальные id категорий, `title` — названия. Карта строится из
  `Store` (корни и их поддерево), а не хардкодится.
- В `renderCategories` ключ группы приходит из маршрута; в
  `openCategoryModal` он передаётся явно. Таблица получает нужный набор
  строк; модалка знает, в какую группу создавать категорию.
- В модалке убираем только чекбокс **«Категория кораблей»**; тип берётся из
  группы: «Корабли» — корень `isShip = true`, остальные — `false`,
  подкатегории наследуют. Остальную вёрстку модалки не трогаем.
- Вёрстка таблицы не меняется: те же колонки, бейджи «корабль», счётчики,
  кнопки. Меняется только источник строк — выбранная группа. Бейджи
  «корабль» остаются.
- Кнопка «Добавить категорию» создаёт подкатегорию корня открытой группы;
  «Подкатегория» в строке — вложенную. Родитель выбирается только внутри
  своей группы.
- Корень нельзя удалить: кнопка «Удалить» остаётся на месте (вёрстку не
  трогаем), но обработчик показывает отказ «Корневую категорию удалить
  нельзя». Подкатегории удаляются как раньше.
- У корня имя и родитель фиксированы: группа ищется по имени, и
  переименование создало бы второй корень. Свойства и иконку менять можно.

### 16.3. Магазин

- Табы: `Все`, `Оборудование`, `Ресурсы`, `Корабли` — строго в этом порядке,
  из корневых категорий Store. Старый фолбэк `weapon/shield/resource/ship`
  убираем.
- Клик по корню показывает его прямые подкатегории в строке под табами:
  - Оборудование — 10 категорий из § 16.1;
  - Ресурсы — Материалы, Топливо;
  - Корабли — Линкоры, Фрегаты, Корветы, Перехватчики, Шаттлы, Грузовозы.
- Клик по подкатегории фильтрует список; повторный клик снимает фильтр.
- «Все» показывает всё, список группируется по корням/подкатегориям.
- Пустая подкатегория (например, «Топливо») показывает «В этой категории
  пока нет объектов», без выдуманных позиций.
- Левая панель корабля, «На корабле» и вкладка «Ангар» (перегрузка) в этом
  этапе не меняются.

### 16.4. Данные и Store

- `Store.ensureCatalogGroups()` находит или создаёт три корня по именам
  «Оборудование», «Ресурсы», «Корабли»; «Корабли» — с `isShip = true`.
  Функция идемпотентна, дубликаты не создаёт.
- `Store.catalogGroups()` отдаёт клиентскую карту трёх групп:
  `{ equipment, resources, ships }`, у каждой — `title`, `root` и `items`
  (прямые подкатегории). Её используют админка и магазин.
- Одноразовая миграция старых данных:
  - корневые категории, не являющиеся тремя группами, переносятся:
    корабельные (`isShip` или класс корабля) — в «Корабли», ресурсные
    (есть объекты-ресурсы или имя «Топливо») — в «Ресурсы», остальные —
    в «Оборудование»;
  - старые группы «Металлы», «Минералы», «Прочее» и дубли
    «Материалов»/«Топлива» раскрываются: их объекты уходят в «Материалы»
    (топливо — в «Топливо»), лишние категории удаляются;
  - все не-топливные ресурсы, лежащие прямо в корне «Ресурсы», переносятся
    в «Материалы»; «Топливо» остаётся отдельной пустой категорией;
  - пользовательские категории внутри «Ресурсов» не трогаются;
  - категории с уже заполненным родителем не двигаются; циклы проверяются.
- Демо-данные приводятся к дереву § 16.1; порядок корней и подкатегорий
  фиксируется в этом порядке.
- Новых коллекций нет: меняются только `parentId`/`isShip` и состав
  категорий.

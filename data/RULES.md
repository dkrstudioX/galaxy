# data/ — правила мира

Слой данных (`data/store.js`) — общий для ангара, админки и карты «Солнечной
системы». Здесь записаны правила, по которым считаются масса, слоты, трюмы,
контейнеры, топливо и покупка.

Это **договор**. Реализация обязана следовать этим правилам; менять правила —
только вместе с этим файлом, а не «по ходу кода». Если код расходится с
файлом — прав код приводим к файлу, а не наоборот.

## 1. Масса

Считаем **только массу**. Объём, энергия, охлаждение, экипаж — отложены (§ 6).

```
масса(предмет) = масса(предмет) × количество
               + Σ масса(всего, что внутри его слотов)

масса корабля  = масса корпуса + Σ масса(всего, что в его слотах и трюмах)
```

Правило ровно одно: **каждый объект учитывается один раз** — на своей глубине.
Отдельные слагаемые «оборудование в слотах», «оборудование в трюмах», «груз в
контейнерах», «топливо в баках» поддерживать не нужно: одна рекурсивная функция
даёт все эти корзины сразу и задвоить объект не может.

- Ресурсы массы не имеют: **единица ресурса = единица груза** (`Store.cargoUnits`).
- Содержимое контейнера идёт в массу как груз, содержимое бака — как топливо.
- **Груз вне контейнера не существует.** Не «невесом» — его нельзя разместить.
- Топливо вне бака разместить нельзя.

## 2. Роли предметов

| Роль | Что это | Где может лежать |
|---|---|---|
| **оборудование** | имеет массу | крепление, трюм |
| **груз** (ресурс) | массы нет, считается единицами | только в контейнере, только из его списка ресурсов |
| **топливо** | массы нет, считается единицами | только в баке |

- **Контейнер** («грузовой отсек») — это оборудование, которое хранит груз.
- **Бак** («топливный бак») — это оборудование, которое хранит топливо.
- Контейнер и бак — оборудование: их собственная масса считается как масса
  оборудования, а содержимое — как груз/топливо. Один объект не может быть
  одновременно оборудованием и грузом.

Термин: **экземпляр** — конкретная единица в слоте или трюме: «предмет +
количество». У экземпляра-контейнера и экземпляра-бака есть собственное
содержимое (что именно в нём лежит).

## 3. Слоты и трюм

- **Крепление** — точка монтажа одного предмета. Что встанет в крепление,
  задаёт его тип: `item.slotId === slot.id`. Лазер нельзя поставить в крепление
  для пушек, в крепление для пушек — только пушки.
- **Слоты не уникальны.** У корабля может быть несколько одинаковых креплений, и
  в каждом — одинаковое оборудование (две орудийные башни, в обеих одна и та же
  пушка).
- **Трюм — точка монтажа** для оборудования. Его лимит — **свойство корабля**
  «Вместимость трюма» (кг), рядом со «Скорость», «Скорость поворота».
  В трюм можно положить оборудование суммарной массой не больше лимита.
- В трюме может лежать **несколько одинаковых** предметов — поэтому содержимое
  хранится как «предмет + количество», а не как один предмет.
- У контейнера и бака есть **свои внутренние слоты**: в них лежит груз или
  топливо.

## 4. Грузовые отсеки: только свои ресурсы

Контейнер рассчитан на **определённый набор ресурсов**, и это его свойство:
«только камень», «камень и металл», «летучие материалы». Ресурс не из списка в
контейнер не положить: контейнер для летучих материалов камень не хранит.
Несколько разных ресурсов в одном контейнере — только если он рассчитан на них.

Набор ресурсов задаём **свойствами**, а не отдельными типами контейнеров.

## 5. Покупка

Покупка — это установка, и у неё всегда есть адрес.

| Что покупаем | Куда | Условие |
|---|---|---|
| оборудование с креплением | свободное крепление своего типа | есть свободное крепление |
| оборудование, контейнер, бак | трюм | свободное место по массе |
| груз | контейнер | контейнер рассчитан на этот ресурс |
| топливо | бак | — |
| корабль | док | хватает кредитов |

Если свободного крепления нет, в трюме нет места или контейнер не берёт этот
ресурс — **купить нельзя**: кнопка заблокирована с указанием причины.

Клик по пустому слоту открывает в магазине товары под него (категория и
подкатегория) — уже сделано.

## 6. Отложено — сейчас не реализовывать

- **Объём** и проверка `volume_ok()`. Считаем только массу.
- **`power_ok()`, `cooling_ok()`, `crew_ok()`** (энергия, охлаждение, экипаж).
  Свойств в данных нет; проверок нет. Появятся позже — тогда станут
  обязательными.
- Отдельные вместимости под разные трюмы одного корабля. Пока лимит один —
  свойство корабля «Вместимость трюма», он же на каждый трюм.

## 7. Состояние данных: что ещё не соответствует

Чек-лист для реализации (по мере приближения к этим правилам):

- [ ] признак роли у объекта (`оборудование` / `груз` / `топливо`) вместо
      вывода из дерева категорий;
- [ ] признак контейнера и список разрешённых ему ресурсов;
- [ ] признак бака и «Вместимость» бака (сейчас тоннаж бака лежит в «Масса»);
- [ ] «Вместимость трюма» в свойствах корабля;
- [ ] одна рекурсивная функция массы вместо `Store.usedMass` «в лоб»;
- [ ] ресурсы не «любой слот»: груз ходит только во внутренние слоты
      контейнера, а не в крепления;
- [ ] внутренние слоты контейнера/бака доступны в админке (сейчас раздел
      «Слоты и содержимое» показывается только кораблям).

Совместимость по типу крепления (`item.slotId === slot.id`) уже есть —
проверять надо ею.

# JSON положений планет: симметричная кеплеровская модель

> **Статус: реализовано.** 23.10.2026.
>
> Результат: `space/data/planet-positions.json`.

## Цель

Дать готовый JSON с положениями восьми планет Солнечной системы для игры.
Данные считаются локально по кеплеровским элементам, без внешнего API и без
лимита «31 запрос в месяц». Модель стилизованная: она не выдаёт актуальную
эфемериду, но сохраняет реальные эксцентриситеты, наклоны, узлы и периоды,
поэтому орбиты и взаимные расстояния выглядят правдоподобно.

## Трактовка «симметричной модели»

Симметрия — в эклиптических долготах планет на эпоху:

- Меркурий — 0°, Венера — 45°, Земля — 90°, Марс — 135°, Юпитер — 180°,
  Сатурн — 225°, Уран — 270°, Нептун — 315°.
- Для каждой планеты берутся реальные `e`, `peri`, `inc`, `node` и период из
  `space/js/data.js`; большая полуось в а.е. — стандартная (таблица ниже).
- По заданной эклиптической долготе решается точка пересечения луча с
  наклонной орбитой; из неё получаются истинная аномалия, радиус и средняя
  аномалия `M0`. Дальше положение в любой момент времени считается как
  `M = M0 + 360° · t / T`.
- Эпоха снимка — `2026-10-23T00:00:00Z` (старт игры). Это не реальное
  расположение планет на эту дату; в JSON явно стоит `isActualEphemeris: false`.

Стандартные большие полуоси, а.е.:

| Планета | a, а.е. |
|---|---:|
| Меркурий | 0.387098 |
| Венера | 0.723332 |
| Земля | 1.000000 |
| Марс | 1.523679 |
| Юпитер | 5.20260 |
| Сатурн | 9.55491 |
| Уран | 19.21845 |
| Нептун | 30.11039 |

## Схема JSON

Файл: `space/data/planet-positions.json`.

```json
{
  "schema": "galaxy.planet-positions/1",
  "generatedAt": "2026-10-23T00:00:00Z",
  "epoch": "2026-10-23T00:00:00Z",
  "model": {
    "name": "symmetric-keplerian",
    "isActualEphemeris": false,
    "symmetry": { "type": "ecliptic-longitude", "offsetDeg": 0, "stepDeg": 45 },
    "coordinateSystems": {
      "positionAu": "гелиоцентрическая эклиптическая J2000, x/y/z, AU",
      "positionMap": "raw-координаты карты: x вправо, y вниз, z вверх"
    }
  },
  "planets": [
    {
      "id": "mercury",
      "name": "Mercury",
      "ru": "Меркурий",
      "color": "#b5b5b5",
      "orbit": {
        "semiMajorAxisAu": 0.387098,
        "semiMajorAxisMap": 70,
        "eccentricity": 0.205636,
        "perihelionLongitudeDeg": 77.458,
        "inclinationDeg": 7.005,
        "ascendingNodeLongitudeDeg": 48.331,
        "periodDays": 87.969,
        "meanMotionDegPerDay": 4.092350714,
        "meanAnomalyAtEpochDeg": 304.464359,
        "meanLongitudeAtEpochDeg": 21.922359,
        "trueAnomalyAtEpochDeg": 282.3289
      },
      "positionAu": { "x": 0.353649225, "y": 0, "z": -0.032460045 },
      "distanceAu": 0.355135789,
      "longitudeDeg": 0,
      "latitudeDeg": -5.244256,
      "positionMap": { "x": 63.951366, "y": 0, "z": -5.86984 },
      "distanceMap": 64.220185
    }
  ]
}
```

В массиве `planets` — все восемь планет в порядке от Меркурия к Нептуну.
`positionAu` — физические координаты в а.е.; `positionMap` — те же положения
в сжатых игровых единицах, совместимые с `keplerPos3`/`orbitPoint3` из
`space/js/math.js`.

## Изменения

- Новый файл `space/data/planet-positions.json` со снимком модели.
- Новая папка `space/data/` (если её ещё нет).
- После реализации — строка в `plans/README.md` и статус «реализовано» в этом
  плане.

Код игры и `space/js/data.js` не меняются: JSON самодостаточен, а модель
описана в метаданных. Генератор на Python в этот шаг не входит; если понадобится
ежедневная перегенерация, добавим отдельным планом.

## Проверка

- JSON разбирается стандартным парсером, в `planets` ровно 8 записей.
- `longitudeDeg` равны 0, 45, 90, …, 315 (с точностью до 1e-5).
- `distanceAu` лежит между `a·(1−e)` и `a·(1+e)`.
- `positionMap` совпадает с расчётом `keplerPos3(p.dist, …, M0, 0)`.
- В файле нет обращений к сети; данные воспроизводимы локально.
- Визуально положения образуют симметричную «розу» вокруг Солнца, а не
  сбиваются в один сектор, как реальные планеты на 23.10.2026.

## Критерии готовности

- JSON создан, проверен и закоммичен в отдельной ветке.
- План отмечен как реализовано, `plans/README.md` обновлён.
- Пользователь подтвердил, что схема и трактовка симметрии подходят.

## Открытые вопросы

- Если нужен не один снимок, а 31 дневной снимок в одном файле — добавим
  массив `days` или отдельный генератор.
- Если под «симметрией» имелось в виду равномерное распределение не по
  эклиптической долготе, а по средней аномалии (или реальные долготы J2000),
  модель можно пересчитать.

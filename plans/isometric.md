# План: изометрический вид карты «Солнечная система»

> **Статус: реализовано.** Проекция 2:1, `space/js/iso.js`, экранная система
> рисования и изометрические слои есть в коде; проверено 22.10.2026.
> Чек-лист ниже оставлен как исторический список проверок.

Документ описывает перевод `space/` из плоского вида сверху в изометрию 2:1
по референсам `map3.svg`, `map4.svg`, `map5.svg`, `map6.svg`, с сохранением
физики, данных и поведения карты. Эталон композиции — `map5.svg`.

**Коротко:** 9 этапов, 1 новый модуль (`js/iso.js`), правки в 10 файлах,
пересборка `app.js`. Симуляция, орбитальная механика, хранилища баз и
взаимодействие не меняются — меняется только слой отрисовки.

это почти фон `#020205`, `#05060c`).

## 2. Аудит кода: как карта рисуется сейчас

### 2.1 Цепочка кадра

```
main.js:39 frame()
 ├ state.simDays += dt·timeScale
 ├ updateFlyTo() · updateBaseRemovals()
 ├ ctx.clear → renderScene(ctx)         js/render.js:35
 │   ├ drawSky()                        js/sky.js   (экран, свой параллакс)
 │   ├ ctx.translate(W/2,H/2) → scale(zoom) → translate(−cam)   render.js:48–51
 │   ├ drawStars()                      render.js:200
 │   ├ smallBodyList() → clusterBodies()                         сцена/слипание
 │   ├ drawSmallBodies()                smallbodies.js:342
 │   ├ drawSun() · планеты · луны        render.js:211, 224, 254
 │   ├ drawGroupLabel()                 render.js:273
 │   └ drawBases()                      bases.js:538
 └ drawHover() · drawSelection()        hover.js:22, 42
```

Ключевое: **мир и экран различаются только масштабом**. Всё, что рисуется,
рисуется в мировых координатах, а `zoom` равномерно умножает обе оси
(`render.js:49`). Поэтому орбиты — круги, тела — круги с обводкой, толщины
и кегли делятся на `zoom` вручную (`10 / zoom`, `1 / zoom` — десятки мест).

### 2.2 Узлы, которые мешают изометрии

| Узел | Файл:строка | Что мешает |
| --- | --- | --- |
| Мировой transform | `render.js:48–51` | Равномерный `scale(zoom, zoom)`; нет сжатия оси Y |
| `screenToWorld` | `math.js:44` | Обратное преобразование без сжатия |
| Зум к курсору | `input.js:22–32` | Сдвиг камеры `(1/z0 − 1/z1)` без учёта сжатия по Y |
| Панорамирование | `input.js:65, 134–135` | `dy / zoom` вместо `dy / (zoom·K)` |
| Слипание тел | `scene.js:54–56` | Порог `MERGE_PX / zoom` в мировых единицах; при сжатии расстояние искажается |
| Hit-тест | `hover.js:77–113` | Сравнение в мировых единицах — область попадания станет эллипсом |
| Орбиты hover/выбора | `hover.js:117–145` | Рисуются мировым `arc` |
| Солнце / планеты / луны | `render.js:211–262` | Круги с обводкой, без заливки, без тени, без порядка по глубине |
| Подписи групп | `render.js:273–297` | Текст в мировом transform → при сжатии шрифт сплющится |
| Базы: маркер, подпись, превью | `bases.js:582–706, 732–778` | Квадрат, пульс, подпись и бегущая строка в мировых единицах |
| Малые тела | `smallbodies.js:342–470` | Пояс — круги в мире, пыль — `fillRect` в мире |
| Кометы | `smallbodies.js:425–470` | Хвост в плоскости, без высоты и шпильки |
| Небо | `sky.js:202–203` | Вертикальный параллакс `camY·zoom` без сжатия (мелочь, но заметна) |

Порядок отрисовки тоже плоский: малые тела → солнце → планеты → подписи →
базы. Нет понятия «дальше/ближе»: планета за солнцем не прячется за его
гало, а рисуется поверх.

## 3. Целевая модель

### 3.1 Проекция 2:1

Ортогональная проекция плоскости эклиптики с наклоном `atan(0.5) ≈ 26.57°`
(классическая «изометрия 2:1», ровно как в референсах):

```
sx = W/2 + (x − camX) · zoom
sy = H/2 + (y − camY) · zoom · ISO_K        ISO_K = 0.5
```

Следствия:
- окружность радиуса `R` в мире → эллипс `rx = R·zoom`, `ry = R·zoom/2`;
- вертикальный экстент системы уменьшается вдвое (Нептун 780 → 390 px при
  `zoom = 1`) — карта становится шире, чем выше;
- высота над плоскостью в проекции не участвует (см. 3.3).

Константа — `config.js`:

```js
export const ISO_K = 0.5;   // 2:1, наклон плоскости ≈ 26.57°
```

### 3.2 Единственная система рисования — экранная

Вместо `ctx.scale(zoom, zoom)` рисуем **в пикселях**, а мир переводим одной
функцией. Это убирает целый класс ошибок «забыл поделить на zoom / забыл
контрмасштаб» и делает толщины, пунктиры и кегли постоянными на экране.

```js
// math.js
export function project(x, y, state) {
    return {
        x: state.W / 2 + (x - state.camX) * state.zoom,
        y: state.H / 2 + (y - state.camY) * state.zoom * ISO_K
    };
}

// высота над плоскостью — в экранных пикселях (см. 3.3)
export function project3(x, y, h, state) {
    const p = project(x, y, state);
    p.y -= h;
    return p;
}

export function screenToWorld(sx, sy, state) {
    return {
        x: state.camX + (sx - state.W / 2) / state.zoom,
        y: state.camY + (sy - state.H / 2) / (state.zoom * ISO_K)
    };
}

// орбита в плоскости: центр + радиус → параметры экранного эллипса
export function projectOrbit(cx, cy, r, state) {
    const c = project(cx, cy, state);
    return { cx: c.x, cy: c.y, rx: r * state.zoom, ry: r * state.zoom * ISO_K };
}
```

Правило для всего кода: **плоское (орбиты, пояс, пыль, спицы, световое
пятно) — через `project`, объёмное (шары, ромбы, шпильки, текст, гало) — в
пикселях как есть.**

Альтернатива (сжать сам canvas-transform `scale(zoom, zoom*K)` и
контрмасштабировать объём) отклонена: при неравномерном масштабе толщина
линии зависит от направления (горизонтальная линия становится 0.5 px),
и любой новый элемент молча сплющивается.

### 3.3 Высота над плоскостью — в пикселях

Карта — схема, а не 3D-рендер: высота нужна как пиктограмма «это в объёме,
над полом». Поэтому высота задаётся в экранных пикселях и не зависит от зума:

| Объект | Высота | Почему |
| --- | --- | --- |
| Солнце, планеты, луны, камни | `lift = R` (радиус шара на экране) | шар стоит на плоскости — как в референсе (там 0.9–1.5 `r`) |
| Звёздная база | `BASE_LIFT_PX = 14` | база «в орбите», а не лежит на кольце |
| Комета | `COMET_LIFT_PX · sin(i) · sin(θ)` (0…170 px) | наклон по реальному `i`, узлы на оси X |

Так шпилька и тень всегда читаемы, а комета не улетает за кадр на `zoom = 20`.

### 3.4 Свет и сферы

Свет — сверху-слева, как в референсах (`cx 30%`, `cy 30–34%`). Рецепт
градиента один на все тела:

```
0%   highlight  = mix(color, #ffffff, 62%)
42%  base       = color
100% limb       = mix(color, #0a0e16, 84%)
```

- `createRadialGradient` считается один раз на цвет и кладётся в спрайт
  `256×256` (`js/iso.js`), затем `drawImage` нужного размера. Это дешевле
  сорока градиентов в кадр и не даёт «мыла»: градиент и так мягкий.
- Кант `1 px` `rgba(255,255,255,.16)` — сохраняет «стеклянность» проекта и
  читаемость на тёмном фоне (в референсе его заменяет свечение).
- Гало: радиальный градиент `rgba(255,255,255,.10) → 0` на `1.35 R`. Только
  для солнца, комет, баз и крупных планет (`r ≥ 12`), иначе шум.
- `ctx.filter = 'blur()'` **не используем** — дорого на кадр; мягкость даёт
  сама градиентная заливка.

Солнце (`SUN_R = 22` не меняем — от него зависят коридоры орбит баз,
`bases.js:136`):

```
световое пятно на плоскости: rx = 5R, ry = 2.5R, #ffce7a .18 → 0
гало:      радиус 2.8R, #ffd27a .45 → #ff9d3c .12 → 0
ядро:      R, градиент #fffef7 → #ffe9a8 (40%) → #ffc64d (72%) → #ff9d3c
центр:     0.38R, тот же градиент (яркое ядро)
```

Сатурн: кольцо в экранных координатах, `rotate(−0.26)`, две полосы
(`2.3R × 0.78R` и `1.85R × 0.62R`). Задняя половина — до шара, передняя
(дуга `0…π` в локальной системе) — после шара. Одна запись глубины на
планету, внутри неё — три шага.

### 3.5 Тени и шпильки

```js
// тень тела: центр — в точке плоскости, эллипс 2:1
ellipse(sx, sy, R * 0.95, R * 0.45)   // чёрный, alpha .38, размытие градиентом
```

Шпилька (база, комета): вертикальная линия `1 px` от маркера вниз до
эллипса-тени + сам эллипс (`rx 5, ry 2`) цветом объекта, alpha `.2`.

### 3.6 Слои и порядок отрисовки

```
1. небо (sky.js) — экранный слой, без изменений
2. пол: спицы от солнца, тёплое пятно, полоса пояса, пыль Койпер/Оорт,
        гравий пояса
3. тела по глубине: depth = мировой y, по возрастанию (дальние первыми)
        солнце (depth 0) · планеты · луны · крупные камни
4. объёмные: кометы (ядро + хвост, шпилька), базы (ромб, шпилька, подпись) —
        по возрастанию y
5. подписи групп и имена баз — экранные, в конце (placeLabel)
6. орбита и подсказка hover/выбора — экранные, поверх всего
```

Порядок 3 — то, чего сейчас нет: планета с `y < 0` (дальняя половина)
рисуется до солнца и попадает под его гало, с `y > 0` — поверх, как в
`map4`/`map6`.

Орбита наведения/выбора остаётся **поверх** тел (пункт 6): это отклик
интерфейса, а не геометрия карты — так уже устроено (`main.js:63–65`:
`drawHover` после `renderScene`), и это не создаёт новой связи `render ↔
hover`. На референсах постоянных орбит нет, так что конфликта с ними нет.

Важно: **порядок отрисовки не равен порядку `hoverTargets`**. Приоритет
попадания остаётся смысловым (луны → малые тела → планеты → базы → солнце),
иначе ближняя планета начнёт перехватывать клик у своей луны.

### 3.7 Подписи и hit-тест

- `scene.js placeLabel(x, yTop, w, h)` переводится в **экранные пиксели**:
  шаг строки `h + 2`, без `state.zoom`. Оба вызывающих (`render.js drawGroupLabel`,
  `bases.js drawBaseMarker`) переключаются в том же коммите — иначе коробки
  посчитаются в разных единицах и подписи начнут наезжать.
- Кегли — константы: группы `10px monospace`, базы `600 10px "Manrope"`,
  подсказка `12px monospace`. Все `/ zoom` в тексте удаляются.
- Hit-тест — в пикселях: `dist2 ≤ (rPx + 2)²`, для базы — ромб
  (`|dx| + |dy| ≤ 8`), для кометы — ядро + кома (`rPx + 4`).

### 3.8 Контракт `hoverTargets`

```js
{ kind, name, x, y,        // мир (плоскость) — как сейчас
  rPx,                     // радиус попадания на экране, px
  lift,                    // высота центра над плоскостью, px
  ... }                    // p, m, small, local, moons — без изменений
```

Меняются только поля `r` → `rPx` и добавляется `lift`. Потребители:
`hover.js findBodyAt` (единственный), `input.js` (только факт попадания),
`ui.js` (не использует). Правка локальная.

## 4. Этапы работ

Порядок выбран так, чтобы каждый коммит оставлял карту рабочей. Этапы 1 и 2
в один коммит: промежуточное состояние «плоскость сжата, тела круглые» похоже
на баг.

### Этап 1. Проекция и камера

**Файлы:** `config.js`, `math.js`, `render.js:48–51`, `hover.js:117–145`,
`scene.js:54–56, 102`, `input.js:22–32, 65, 134–135`, `sky.js:202–203`.

1. `config.js`: `ISO_K = 0.5`.
2. `math.js`: `project`, `project3`, `projectOrbit`; `screenToWorld` — с
   делением на `ISO_K`.
3. `render.js`: убрать мировой transform; звёзды, солнце, планеты, луны и
   все потребители `circle()` переводятся на `project` (на этом этапе тела
   ещё круги, но уже в правильных точках).
4. `input.js`: `zoomAt` — `camY += (ay − H/2)/ISO_K · (1/z0 − 1/z1)`;
   панорамирование — `dy / (zoom·ISO_K)` (оба места: мышь и тач).
5. `scene.js`: слипание сравнивает **экранное** расстояние
   (`dx`, `dy·ISO_K`), `MERGE_PX` остаётся 50 px.
6. `sky.js`: вертикальный параллакс умножить на `ISO_K` — небо едет вместе
   с миром.

**Готово, когда:** орбита планеты — эллипс ровно 2:1; при панорамировании
карта следует за курсором по обеим осям; колесо удерживает точку под
курсором; радиус орбиты базы в режиме создания совпадает с курсором.

**Проверка:** временная отладочная сетка `100×100` мира (квадраты должны
остаться квадратами в мире и стать прямоугольниками 1:0.5 на экране) и
окружность из 12 точек (эллипс 2:1). Удалить после проверки.

### Этап 2. Тела-сферы и глубина

**Файлы:** новый `js/iso.js`, `render.js:211–262`, `build.py`, `index.html`.

1. `js/iso.js` — примитивы: `sphere(ctx, sx, sy, R, color)`,
   `shadow(ctx, sx, sy, R)`, `rock(ctx, sx, sy, R, seed, color)`, `halo`,
   `diamond`, `pin`, кэш спрайтов по цвету.
2. `render.js`: `drawSun`, `drawPlanetBody`, `drawMoonBody`, `drawRings`
   переписываются на сферы (3.4) с тенью и подъёмом `lift = R`.
3. `render.js`: собрать список `{depth, draw}` для солнца, планет и лун;
   `sort((a, b) => a.depth − b.depth)`; `depth = world y`. Малые тела
   встают в этот список на этапе 6, до него — блоком под телами, как сейчас.
4. `build.py`: в `ORDER` добавить `'iso'` после `'state'` (сборка склеивает
   файлы по порядку — без этого `app.js` упадёт на `undefined`).
5. `index.html`: поднять `?v=` у `app.js`.

## 5. Риски и как их снимаем

| Риск | Почему | Решение |
| --- | --- | --- |
| Двойное сжатие текста | Кто-то нарисует `fillText` под `project` | Правило: текст только в px; на ревью искать `fillText` рядом с `project` |
| Подписи наезжают | `placeLabel` в px у двух вызывающих | Переключить `render.js` и `bases.js` одним коммитом; `placeLabel` хранит px |
| Клик не туда | Hit-тест в мировых единицах стал эллипсом | Контракт 3.8: `rPx` + `lift`, тест в px |
| Луна перехватывает клик у планеты / наоборот | Порядок `hoverTargets` начнут выводить из порядка отрисовки | Разделить: `drawOrder` (глубина) и `hitOrder` (смысловой, как сейчас) |
| Тормоза | Градиенты и `blur` на каждый кадр | Спрайт-кэш сфер, никакого `ctx.filter`, гало только у крупных |
| Забыли пересобрать | Страница грузит `app.js`, а не модули | `py build.py` + `node --check app.js` в конце каждого этапа, `?v=` |
| Сборка падает | `build.py` склеивает по жёсткому `ORDER` | `iso` вставить после `state` (этап 2, п. 4) |
| Физика «поехала» | Соблазн сжать и мировые координаты | Мир не трогаем: `dist`, `orbitAngle`, `keplerPos`, коридоры баз — как были |
| `zoom` 0.3: пояс звенит | Точки меньше пикселя | Минимум `0.7 px`, цвет с alpha вместо уменьшения |
| HiDPI | Канвас 1:1 с CSS-пикселями (было и раньше) | Вне рамок; экранная система координат делает переход на DPR дешёвым позже |

## 7. За рамками и открытые вопросы

- **Корабли** (треугольники на референсах) не переносим — в проекте их нет.
- **Постоянные орбиты** не вводим: пунктир остаётся только у hover/выбора,
  как записано в `ARCHITECTURE.md`. Наклонная орбита кометы — тоже только
  по наведению.
- **Наклон колец лун** (как в `map4`) не делаем: луны в проекте ходят в
  плоскости эклиптики, и наклон кольца разошёлся бы с их реальным
  положением. Если нужен именно этот приём — это отдельная задача с
  переводом лун в 3D (и пересчётом коридоров баз).
- **Вращение камеры** (свободный изометрический угол) не делаем: угол
  фиксирован `ISO_K = 0.5`.
- **Начальное кадрирование:** сейчас `zoom = 1`; после сжатия по Y система
  стала шире, чем выше. Можно один раз на старте подобрать зум под окно
  (`fit`) — решается после этапа 2, по внешнему виду.
- **Цвет базы** (этап 9) — продуктовое решение, не техническое.

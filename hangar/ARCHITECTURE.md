# hangar/ — ангар и торговый терминал

Статическая страница: открывается как `file://` или с любого статического
сервера. Node, npm и сборщики не нужны. Исходники — ES-модули в `js/`,
рабочий файл `hangar.js` собирается Python-скриптом `build.py`.

Данные мира — общие: `../data/store.js` (localStorage `galaxy_admin_db_v1`),
иконки — `../data/icons.js`. Правила мира — `../data/RULES.md`, план работ по
данным — `../plans/data.md`. Стиль интерфейса общий с `space/` и описан в
корневом `AGENTS.md`.

## Примеры дизайна

`examples/` — статические макеты-эксперименты. Они не входят в `build.py`,
не подключают `hangar.js` и `data/store.js` и не влияют на рабочий ангар;
открываются напрямую как HTML. Описание и список примеров — в
`examples/README.md`.

## Сборка

```
cd C:\work\GalaxyAdminPanel\hangar
py build.py
```

`build.py`:

- читает модули в порядке `ORDER` (он же порядок зависимостей);
- убирает строки `import ...;` и префиксы `export`;
- заворачивает всё в один IIFE со `'use strict'`;
- пишет `hangar.js`.

`hangar.js` — **сгенерированный** файл, править его нельзя: изменения
потеряются при следующей сборке. Правим только `js/*.js`, затем пересобираем.
`index.html` подключает один `hangar.js?v=...`; при изменениях версию в
`index.html` нужно поднять, иначе браузер отдаст старый файл из кеша.

## Слои и поток данных

```
data/store.js ──► catalog.js ──► categories.js ──► ship.js
      (база)       (витрина)      (фильтры)        (корабль)
                                                      │
state.js ─────────────────────────────────────────────┤
                                                      ▼
                       shop.js · ship-view.js · info.js · hangar-tab.js · dock.js
                                                      │
                                                      ▼
                                                   DOM (index.html)
                                                      ▲
                                          app.js — рендер, клики, покупка/продажа
```

- `data/store.js` — единственный источник данных мира: объекты, категории,
  шаблоны слотов, записи купленных кораблей, масса, цены, кредиты.
- `catalog.js` один раз при загрузке вызывает `Store.ensureCatalogGroups()`
  (миграция старых баз в три группы), затем строит строки витрины
  (`shopItems`) и табы категорий (`categories`) из `Store.catalogGroups()`.
- `state.js` — только состояние интерфейса (вкладка, фильтры, выбранный
  корабль/предмет). Данные мира в нём не хранятся.
- `app.js` — единственное место, где меняется `Store`: покупка, продажа,
  кредиты. После действия вызывается `render()` и `renderDock()`.

## Модули

| Файл | Ответственность | Зависит от |
| --- | --- | --- |
| `js/base.js` | SVG-иконки (`icon`, `iconMarkup`, `iconForCategory`, `shipGlyph`), `fmt`, `plural`, `pad2`, `byId`, `isMassName`, общее окно `openDialog` | — |
| `js/state.js` | объект `state`: вкладка, категория/подкатегория, выбранные корабль и предмет, режим перегрузки, демо-запас «Ангара» | — |
| `js/catalog.js` | `shopItems` из `Store.objects()`, табы трёх групп (`categories`) из `Store.catalogGroups()`, `hangarResources` | `base` |
| `js/categories.js` | дерево категорий: `inSubtree`/`inCategory`, `buildSubcategories`, `filteredItems`, `itemSubcategoryId`, `groupedShopItems`, `currentShop`, `activeResource` | `base`, `catalog`, `state` |
| `js/ship.js` | запись корабля (`userShipRecords`, `activeUserShip`, `activeShipView`), оборудование в креплениях и трюмах, квадраты слотов и трюмов, панель «01 Корабль», колонка «На корабле», модальные окна и подсказки | `base`, `state`, `catalog`, `categories` |
| `js/shop.js` | вкладка «Магазин»: табы, чипы, список «В продаже», консоль (купить / сведения), колонка «На корабле» | `base`, `state`, `catalog`, `categories`, `ship` |
| `js/ship-view.js` | вкладка «Информация о корабле»: шапка, оборудование, трюмы, слоты | `base`, `ship` |
| `js/info.js` | вкладка «Информация о базе»: карточка HELIOS VII и ресурсы | `base`, `state`, `catalog` |
| `js/hangar-tab.js` | вкладка «Ангар»: перегрузка ресурсов база ↔ корабль (пока демо-запас в `state`) | `base`, `state`, `catalog`, `categories` |
| `js/dock.js` | нижний док: карточки купленных кораблей и выбор активного | `base`, `ship` |
| `js/app.js` | каркас: шапка, вкладки, `render`, `renderShipView`, делегирование кликов, подсказки, старт; покупка/продажа и кредиты | все модули |

Порядок в `build.py`:

```
base → state → catalog → categories → ship → shop →
ship-view → info → hangar-tab → dock → app
```

Зависимости идут только вперёд по этому списку; циклических импортов нет.
`app.js` — последний, он связывает модули и запускает приложение.

## Ключевые понятия

- **Витрина** — плоский список `shopItems`; каждый объект знает `categoryId`,
  `parentCategoryId`, `mass`, `price`, `sale`, `slotId`, `isShip`.
- **Группы** — три постоянных корня каталога: «Оборудование», «Ресурсы»,
  «Корабли». В магазине это табы после «Все»; ресурсы делятся на
  «Материалы» и «Топливо», корабли — на классы. Состав групп задаёт
  `Store.catalogGroups()`, старые базы приводит к нему
  `Store.ensureCatalogGroups()`.
- **Ветка** — выбранная категория плюс необязательный чип подкатегории;
  она задаёт фильтр витрины, но не заголовки групп.
- **Группы списка** — `groupedShopItems` всегда кладёт позиции под фактическую
  подкатегорию товара (первый уровень под корнем), независимо от выбранного
  таба/чипа. Заголовок группы показывается всегда, в том числе для одной группы.
  `cargoListHTML` в «На корабле» использует то же правило.
- **Корабль** — запись `Store.userShips()`: `shipId`, `slots[]`, `holds[]`.
  `activeShipView()` отдаёт запись, объект корабля, крепления и трюмы.
- **Слот** — крепление ровно под один предмет. **Трюм** — место под любое
  число предметов в пределах массы; предметы показываются квадратами.
  Клик по заполненному квадрату (слот или трюм) — это выбор предмета:
  магазин открывается на его категории, выделяется только строка в «На корабле»
  (витрина не выделяется), справа — карточка предмета с продажей. Пустой слот
  открывает совместимые товары.
- **Груз контейнера** — значки ресурсов в углу квадрата. Наведение даёт
  подсказку (ресурс, контейнер, кг, цена); клик по значку выбирает груз
  в «На корабле» и предлагает «Продать 1 кг» (`Store.sellCargo`). Клик по
  остальной части квадрата выбирает сам контейнер — его можно продать
  целиком вместе с грузом. В магазине у контейнера — блок «Можно положить»:
  материалы из `prop_2` и вместимость, теми же стилями, что и состав.
- **«На корабле»** — реальное оборудование и груз записи: каждая единица
  отдельно, строки как в витрине, фильтр по текущей ветке, клик показывает
  карточку (место, масса/кг, цена) и кнопку продажи. У контейнера с грузом
  в карточке — список ресурсов с килограммами и итог, ниже — только «Продать
  вместе с грузом»: подтверждение с составом и общей суммой, затем
  `Store.sellEntry(..., withCargo=true)`.
- **Продажа корабля** — карточка купленного корабля показывает разбивку
  `Store.shipSaleValue`: корабль, оборудование, груз и итого. «Продать
  корабль» открывает подтверждение с той же разбивкой; `Store.sellShip`
  удаляет запись и начисляет сумму за корабль вместе с содержимым.
- **Модальные окна** — общий паттерн `.slot-modal`/`.slot-dialog`: тёмный
  оверлей, eyebrow, заголовок, квадратная «×». Закрытие — клик по оверлею,
  «×» или `Esc`.

## Как менять

- **Новая панель/вкладка.** Добавить модуль в `js/`, внести его в `ORDER`
  перед `app.js`, импортировать рендер в `app.js` и вызвать из `render()`.
- **Новое действие.** В разметке — `data-action="..."`; в `app.js` — ветка в
  делегированном обработчике кликов; после изменения `state`/`Store` вызвать
  `render()` (и `renderDock()`, если менялись корабли).
- **Новое поле интерфейса.** Добавить в `state.js`, сбрасывать при смене
  корабля/ветки там, где это требуется.
- **Новая цена/масса/свойство.** Считать через `Store` (`massOf`,
  `priceBuy`, `priceSale`, `shipMass`), не дублировать формулы в рендере.
- **Стили.** Только `hangar.css`; новые элементы — по образцу соседних
  панелей, без собственных палитр и крупных скруглений.

После правок: `py build.py`; если менялся `hangar.css` — поднять `?v=` у него
в `index.html`; проверить вкладки и действия в браузере.
